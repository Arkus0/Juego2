# Agent Model Policy — Juego2

Version: 1.0 — 2026-09-18

Do not bind repository correctness to one vendor/model name. Bind roles to capability requirements.

## Architect

Use a high-reasoning model for milestone architecture, dependency resets, foundational contract design and repeated-failure analysis.

## Foundational Worker

Use a strong coding/reasoning model. HK work requires proof design, not only code generation. A cheaper/faster model may execute bounded mechanical edits, but the owning Worker remains responsible for completeness and evidence.

## Reviewer

Prefer the strongest available independent reasoning configuration. Reviewer quality has higher value than raw throughput because a false PASS contaminates every downstream WP.

Independence is contextual, not merely model-brand diversity: a fresh session of the same model may be independent; a different model carrying Worker implementation context is not.

## Routine DocSync / recovery

May use faster models when the transition is mechanically constrained and all authoritative state comes from GitHub.

## Escalation

Escalate to a stronger reasoning model when:

- a foundational claim receives FAIL;
- two repair loops expose the same class;
- contract sources conflict;
- the proposed fix grows syntax-specific exceptions;
- scope/dependency architecture may need reset.
