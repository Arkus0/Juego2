# WP-HK-00 — Residual risk audit

The standard asks whether residual risk can still falsify the central claim.
The central claim of WP-HK-00 is narrow:

> There is a canonical, engine-free, acyclic, single-ownership module boundary,
> built by a pinned toolchain, whose declared shape matches what the compiler and
> the produced binaries actually did, and whose guards fail closed.

Everything below is a known limitation, stated with what bounds it. None of these
is a defect class that would leave the central claim false while CI is green;
where that judgement is close, it is argued rather than asserted.

## 1. The forbidden-name list is a list

`forbiddenAssemblyNamePatterns` cannot recognise an engine that ships under an
unrelated assembly name.

*Bound:* the name list is a convenience, not the boundary. Production classes may
take **no** NuGet dependencies and **no** raw assembly references at all, and
every kernel assembly's reference table must equal its declared project edges.
An engine could therefore only enter as a new classified project with a benign
name, which is a reviewable manifest change, not a silent one.

## 2. Analyzer and compiler behaviour ride on the SDK feature band

The pin fixes `8.0.1xx`, not an exact patch. A later patch could change which
warnings exist.

*Bound:* warnings-as-errors is enforced at three layers, so a *new* warning
breaks the build rather than passing silently. The risk is the opposite
direction — a warning disappearing — which weakens quality but cannot make the
boundary claim false. The exact SDK of each run is recorded in
`artifacts/proof/report.json`.

## 3. Only `.cs` files are inventoried

`.resx`, source generators and other non-`.cs` production inputs are not
classified.

*Bound:* none exist today. Any generated source that reaches the compiler must
match the expected-generated allow-list, or `HK00-SOURCE-UNEXPECTED-GENERATED`
fires — proven by the `hidden-generated-source` attack. A future workpack that
introduces source generators must extend the inventory before relying on this
one's ownership claim.

## 4. The proof tool is trusted to report honestly

A tool that lies is not detectable by itself.

*Bound:* the tool's own decision logic (cycle detection, pin rules, name
matching, path containment, command-line parsing, manifest fail-closed
behaviour) is unit-tested — 69 tests — and it is deliberately separable: the
Reviewer can re-derive the same facts with `dotnet msbuild -getProperty`,
`-getItem`, a PDB reader and `ProvideCommandLineArgs` without using this tool at
all. The tool is also required to exist: deleting it fails preflight rather than
shrinking the run.

## 5. Runtime composition is not constrained, only reference-level layering

Reflection could reach past the declared layering at runtime.

*Bound:* nothing in the kernel uses reflection; the whole kernel is 22 production
source files, listed with content hashes in `inventory/sources.json`. This
becomes a real obligation once the runtime gains dynamic dispatch, which belongs
to WP-HK-07.

## 6. The boundary modules are placeholders

`*Module.ComposedModules` exists so declared edges are exercised by real
cross-assembly calls. It is not a harness feature.

*Bound:* this is intended scope. WP-HK-00 claims a boundary, not behaviour. The
placeholders are documented as such in code and in ADR-0001, and WP-HK-01 is
expected to replace them with protocol envelopes rather than build on them.

## 7. Unity compatibility is contractual, not demonstrated

`netstandard2.1` is what Unity can consume; no Unity import was performed.

*Bound:* importing Unity now is explicitly forbidden scope for this workpack and
blocked until `WP-HK-GATE`. The obligation is recorded for H1, where a Unity
parity gate is already on the roadmap.

## 8. Evidence freshness

Documents can drift from the tree they describe.

*Bound:* the mechanical parts are regenerated by the same run that checks them —
`inventory/*.json` is diffed in CI and `self-attacks/results.md` is written by
the attack harness. The prose in this pack is the part a Reviewer must judge, and
it names the exact commands that reproduce every claim.

## Verdict on residual risk

No item above can falsify the central claim while CI is green. Items 3, 5 and 7
are obligations that transfer to named later workpacks rather than open questions
here.
