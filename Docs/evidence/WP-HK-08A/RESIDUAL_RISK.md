# WP-HK-08A residual risk

## Claim boundary

HK08A claims efficient stable interaction primitives over accepted H0 authored-world semantics: one representative 96-operation mixed-resource intent remains one atomic validated/provenanced transaction; `authoring.journal.read@1.0` preserves the accepted complete HK06A read; explicitly negotiated `authoring.journal.read@2.0` provides bounded deterministic pagination tied to the authored journal context; compact reads and canonical discovery support economical interaction; and all changed public shapes remain semantically equivalent through JSONL and MCP.

The proof boundary includes repository-owned canonical contracts/services, HK08A provenance wrappers, Runtime composition, both accepted local transports and focused/full conformance. It trusts accepted predecessor semantics, Git/exact-checkout behavior, the pinned .NET toolchain, normal process/stdio behavior and documented hashing primitives under the foundational proof standard.

Within that boundary, no known material false-green defect class remains after the Worker pre-review and Reviewer-fail repair.

## Non-blocking residuals / named future owners

### Legacy v1 completeness can still be a large response

Compatibility requires `authoring.journal.read@1.0` to keep its accepted complete-journal semantics. Therefore v1 is not retroactively bounded. Clients that want bounded interaction must explicitly negotiate v2. Removing, deprecating or changing v1 would be a later contract-lifecycle decision and cannot be smuggled into HK08A under the same version.

### Paging bounds v2 public responses, not internal journal storage

The process-local provenance authority still owns/materializes its complete HK06A journal, and the v2 paging view slices that accepted artifact. HK08A reduces wire/client interaction size for v2 clients; it does not claim incremental on-disk indexing, streaming persistence, unbounded-history memory scaling or crash durability.

### Paged clients must reconstruct a complete artifact before HK06C replay

A partial v2 response is deliberately marked `arkus.authoring.journal-page@1`, so replay cannot mistake it for a complete journal. A client choosing v2 pagination must collect all pages and reconstruct the accepted complete HK06A artifact before invoking replay. Existing v1 clients may continue reading the complete artifact directly.

### 96 operations is not the final resource envelope

The 96-operation maximum is the bounded envelope needed by the representative HK08A probe, not a performance promise or permanent product limit. HK09B owns measured bytes/depth/time/page/batch limits.

### Stale-CAS recovery is still HK08B

HK08A cursor stale handling is read-pagination correctness. It does not add structured recovery for a mutation planned against an old whole-world revision/hash, automatic merge, diagnostic repair ordering or bounded reinspection strategy. Those remain HK08B.

### Cursor integrity is framing correctness, not authorization

V2 cursors are opaque values whose deterministic envelope detects altered/corrupted continuation context such as an edited offset. The checksum is not a secret MAC and HK08A makes no hostile-client, authentication or access-control claim.

### Process lifetime remains predecessor scope

JSONL/MCP hosts still use the accepted process-local authored session. Cursor lifetime across restart, durable project storage, multi-process writers and distributed coordination are not added here.

### Cost metadata is relative, not a final agent budget

`sideEffect` plus relative canonical cost enables machine-readable cheap-path discovery. It is not a measured token/latency budget or maximum agent-call guarantee. HK08B owns the representative correction benchmark and HK09B the final resource envelope.

### Product-shape probe is synthetic at the H0 semantic layer

The 72 object + 24 extension probe is sized from the approved-draft Potes/Liébana visual-bible envelope while remaining engine-neutral. It does not prove Unity transforms, prefab identity, geometry constraints or asset import.

## Blocking-risk conclusion

None of these residuals falsifies the stated HK08A claim. The concrete Reviewer defect — changing complete-read semantics under `authoring.journal.read@1.0` — is no longer residualized: v1 is restored and a separate major v2 carries the paged contract. The earlier editable-cursor false green is likewise repaired rather than accepted as residual risk.
