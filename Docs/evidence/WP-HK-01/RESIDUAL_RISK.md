# WP-HK-01 residual risk audit

## In-claim status

No known material defect class remains able to falsify HK01 acceptance inside the declared trust boundary after the repair-cycle-2 circuit-breaker re-audit.

The canonical surface currently contains only the H0 `system.describe` base capability; synthetic scoped providers prove that future reviewed provider definitions and bindings can enter the same inventory without redesigning the kernel. World, mutation, validation, provenance implementation, transports and concrete Unity behavior remain owned by later workpacks.

## Non-blocking residual risks

- The schema model intentionally implements the Arkus-required subset of JSON Schema 2020-12, not every keyword in the standard. Expanding that vocabulary later must extend the conservative acceptance relation and projection oracle rather than bypass them.
- Logical-reference namespaces are mechanically constrained to canonical `ref.<provider-id>.<domain>` identities and provider ownership. HK01 does not attempt an arbitrary semantic denylist that guesses whether a lower-case opaque domain token secretly alludes to an engine concept. Reviewed provider semantics remain part of the admission boundary. Actual CLR/editor/runtime objects, assembly-qualified identities, foreign-provider namespaces and logical-reference enums fail closed.
- Cross-provider/shared logical-reference vocabularies are intentionally not introduced by HK01. If later architecture needs a shared Arkus-owned reference authority, it must be modeled explicitly rather than weakening provider ownership.
- Same-major compatibility is deliberately conservative. The implemented relation proves request-acceptance preservation for the supported schema subset; uncertainty and non-request semantic changes are breaking. False-breaking classifications are acceptable for H0, silent false-compatible classifications are not.
- Major-version changes are explicit breaking boundaries and are not required to preserve request acceptance across majors. Clients select a major through `ContractVersionRange`; later compatibility/migration policy may add richer guidance without changing this rule.
- Effective-route enumeration trusts normal .NET assembly loading/reflection behavior and canonical build outputs, as permitted by the foundational trusted base. Arbitrary malicious compiler/runtime/CI subversion is out of claim.
- The production completeness oracle discovers current Arkus production projects under `src`. HK01 has no external plugin loader; a later reviewed loader must extend the independent universe rather than rely only on provider registration metadata.
- Concrete MCP/JSONL projection parity is deferred to HK07. HK01 provides the canonical inventory/projection source those adapters must consume.
- Concrete Unity/editor/runtime types and capabilities are absent. H1 must instantiate the scoped-provider boundary using portable canonical data and prove its own engine parity.
- HK01 declares policy/transaction/provenance metadata but does not implement later authoring transaction, validation or provenance semantics.
- Semantic fingerprints remain collision-safe diagnostics, not correctness authorities. Structural equality and the independent emitted-artifact oracle own correctness decisions.
- The independent projection oracle duplicates the finite public artifact shape as proof machinery. Future public fields must update production projection and oracle; divergence fails closed.

## Dependency/IP

HK01 adds no third-party package or shipped dependency. Existing pinned build/test dependencies remain governed by the accepted HK00 baseline.

## Proof budget

Its seven new attacks protect those concrete classes. The only extra proof-only repair was placing those already-existing seven attacks under the canonical causal-test filter after Worker pre-review detected that they were otherwise regression-only. No growing syntax denylist or trusted-infrastructure hardening was added.
