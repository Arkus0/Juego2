## Central claim

Inside the accepted finite engine-neutral `WorldState` model, every currently owned canonical world invariant is independently enumerable and registered exactly once; effective validation aggregates stable deterministic repairable diagnostics; current and proposed state validation are discoverable/versioned public capabilities; and every accepted public canonical mutation route rejects a proposal that explicit validation rejects before canonical state can change. Expected invalid public requests/states are represented as structured results rather than runtime exceptions.

When source identity is itself invalid because object IDs or extension identities are duplicated, HK05 uses an explicit deterministic policy: report the duplicate at an index-addressable source entry and defer only secondary diagnostics whose own source or specific graph traversal would require selecting one ambiguous representative. Independent uniquely identified components remain reportable in the same pass. Clients repair identity and revalidate only for the diagnostics whose dependency chain was genuinely ambiguous. HK05 consumes, rather than re-proves, the accepted HK01 public-route universe and HK04 closed commit/transaction boundary.

## Independent/effective universes

1. **Invariant universe** — the test-owned `ExpectedOwnedInvariantIds` list is independent of `WorldInvariantCatalog.All` and `WorldValidationEngine.ValidatorInventory`; exact three-way set equality prevents either production list from silently shrinking the proof obligation.
2. **Effective invariant behavior** — `InvariantFixtures()` causes every expected invariant ID to appear in real validator output, so registration alone is insufficient.
3. **Public mutation universe** — accepted HK01 composition owns route completeness. HK05 consumes the effective composed definitions and checks every definition classified `CanonicalMutation`, rather than maintaining a second mutation route list.
4. **Validation/apply semantic oracle** — explicit proposed validation and apply are independently invoked through public dispatch and their effective diagnostic signatures are compared.
5. **Ambiguous-identity semantic oracle** — duplicate object/extension entries carry different secondary defects and duplicate order is inverted. For objects the oracle has both sides of the dependency boundary: a containment result that crosses the duplicated ID must disappear, while a disconnected `cycle.a <-> cycle.b` formed only from unique IDs must remain. Complete diagnostic output including remediation context must stay equal after duplicate-order inversion. The actionability oracle independently proves that the duplicate diagnostic identifies a concrete source index.
6. **Representative content shape** — the Potes probe is deliberately representative only; it is not used to prove invariant completeness.

## Rejection-site ownership split

HK05 newly owns invalid complete-candidate diagnostics, ambiguity policy and the materialization-disagreement fail-closed mapping. HK01 owns schema rejection and HK04 owns mutation-envelope/concurrency/idempotency/planner structured errors. Those predecessor guarantees are consumed; the HK05 audit verifies that its new paths neither introduce an unclassified expected public rejection nor convert inherited structured failures into escaping exceptions.

The re-audit keeps the ownership boundary at HK05's public aggregate layer rather than modifying inherited HK02 invariant semantics. Ambiguity is local dependency information, not a global world mode: source-ambiguous diagnostics defer directly; a unique-source containment diagnostic replays only its own chain to determine whether it touches a duplicated ID. This closes the causal class without special-casing `node.a`, `dup.x`, or `cycle.a` and without reopening HK02/HK04.

The repair adds one bounded dependency check to the existing ambiguity classification and one additional regression method in the same focused class. It does not add generalized provenance, a second semantic registry, or a new commit/route proof mechanism.
