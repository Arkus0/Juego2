## Independently defined universes / oracles

- **A/B access universe:** derived mechanically from every A/B row in accepted CITY-02 §4. CITY-05 §9 is parsed separately and must equal that upstream subject universe before any role comparison.
- **I1–I3 universe:** derived mechanically from every non-I0 CITY-02 §4 row. CITY-06 §5 inherited-depth subjects and §6 Full I1–I3 allocation subjects are parsed separately and must each equal the upstream universe. The current accepted source contains 14 subjects, but no constant `14` defines completeness in provider/oracle execution or the positive relation test.
- **Access semantic oracle:** source-derived CITY-02 required-role flags must be a subset of independently source-derived CITY-05 bound-role flags for every upstream A/B subject.
- **Interior semantic oracle:** source-derived CITY-02 I-depth must equal independently source-derived CITY-06 inherited I-depth for every upstream I1–I3 subject; Full allocation cardinality/identity is separately exact.
- **Allocation relation oracle:** production `CityInteriorRelationOracle` is invoked by `CityDesignWorldProvider.BuildAndValidate` after generic fresh-projection validation. `BuildAndValidate` supplies the I1–I3 obligation set derived from accepted CITY-02, while the oracle inspects only the already projected `DesignFact.Relations`; for every required subject it requires `allocation.<id>` and `depth.<id>` to exist and exactly one literal `allocates-depth` edge to target that subject's own depth fact. The oracle does not consume `AnchoredFactDefinition`, the authority reader used to build the projection, or any relation registry. Its `CityInvariantException` diagnostics carry a stable machine code, `SubjectId`, explicit semantic rule, expected/observed relation detail and CITY-02/CITY-06 source paths. A test-only internal relation-transform seam changes only the authority definition emitted immediately before generic projection; `Dw01RelationPipelineWiringTests` then calls the public `BuildAndValidate` route, proving the generic validator self-confirms the injected missing relation and the production oracle is what turns the delivered pipeline RED. Removing/bypassing that oracle invocation makes the integration test fail because `BuildAndValidate` would return successfully.
- **Provenance oracle:** inherited DW-00 exact source digest + unique anchor resolution is applied separately to all three accepted source documents.
- **Determinism oracle:** fresh rebuild and reversed definition/enumeration order must produce equal normalized representation and digests.
- **H0 boundary oracle:** exact-SHA observer scans accepted H0 assemblies for reverse DesignWorld/CITY-consumer dependencies and confirms DesignWorld's only project reference remains `Arkus.Game.World`.

## Named causal negative-conformance classes

1. **Single access-role weakening:** downstream binding drops one inherited role → semantic validator RED.
2. **Whole role-surface omission:** downstream binding retains subject but drops every role → semantic validator RED.
3. **Self-shrinking A/B registry:** downstream row disappears → independent CITY-02 universe still requires it and REDs.
4. **Interior allocation omission:** Full I1–I3 row disappears → independent CITY-02 universe still requires it and REDs.
5. **Interior over-promotion:** an I0 place enters Full I1–I3 allocation → unexpected-subject RED.
6. **Interior duplicate/cardinality defect:** duplicate allocation row → duplicate-subject RED.
7. **Inherited-depth drift:** CITY-06 depth weakens while CITY-02 stays fixed → depth-mismatch RED.
8. **Missing allocation relation:** projected allocation keeps its fact/fields/universe but loses `allocates-depth`; the generic projection validator self-confirms and production `CityInteriorRelationOracle` throws `city.interior_allocation_relation_missing` with observed `<none>`.
9. **Renamed allocation relation:** projected allocation keeps the same target but changes the relation type; generic validation remains GREEN and the product oracle reports the expected `allocates-depth` edge alongside the observed renamed edge.
10. **Wrong allocation relation target:** projected allocation keeps one `allocates-depth` edge but points to another valid in-universe depth fact; generic validation remains GREEN and the product oracle throws `city.interior_allocation_relation_target_invalid` with expected and observed targets.
11. **Relation cardinality defect:** a projected allocation has one correct and one incorrect `allocates-depth` edge; the product oracle throws `city.interior_allocation_relation_cardinality` before target selection can mask the duplicate.
12. **Projected allocation/depth fact omission:** the independent CITY-02 obligation set still requires both identities even if a synthetic generic universe self-confirms a shrunken projection; product oracle throws the differentiated projection-missing code.
13. **Dangling relation target:** `DesignWorldProjector` rejects an `allocates-depth` target outside its fact universe as `dw.relation_target_outside_universe` before a malformed `InteriorProjection` can be delivered; in-universe cross-subject redirection remains the CITY oracle's responsibility.
14. **Stale authority with equal-looking semantic values:** whole source bytes change → inherited provenance RED.
15. **Enumeration-order dependence:** reverse source-derived definition/order input → canonical digest must remain identical.
16. **Validator-rule execution removed / oracle present but unwired:** an internal harness-only relation transform removes the canonical edge for a real CITY-02 I1–I3 subject while retaining accepted sources, facts, fields, universes and generic self-confirmation; the test invokes public `BuildAndValidate` and requires the production oracle diagnostic. If the single `CityInteriorRelationOracle.Validate(...)` call is removed or bypassed, `BuildAndValidate` returns and this causal integration test fails.
