## Repair-cycle notes

The original Worker pre-review found that the first suite covered object add/remove and extension field changes but did not explicitly cover **extension add/remove**, leaving a material accepted resource class without a causal omission control. `Hk06BNegativeConformanceTests` closes that class with a distinct extension identity, exact independent resource-set comparison, an omission mutant and a false-extra mutant.

Independent review of frozen SHA `bebc1b6165f7228f33dc593534052cd80eb6e041` then found a different HK06B-owned architectural defect: snapshot import was publicly declared `CanonicalMutation + CanonicalTransaction + Provenance Required` while executing as a complete-session rebase and intentionally starting an empty HK06A mutation journal. Repair cycle 1 corrects the **classification ↔ authority ↔ evidence** class rather than adding an exception to mutation conformance. `Hk06BRebaseContractTests` is the causal regression control.
