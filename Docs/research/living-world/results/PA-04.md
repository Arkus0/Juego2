## 0. Boundary

This is the Juego2 Worker candidate for PA-04. It harvests the independently reviewed `Arkus0/Juego` Knowledge/Belief research without importing donor M9/M10 routing, `WorldState` ownership, C# classes, storage schemas, numeric tuning, API topology or old constitutional authority.

PA-04 answers:

> What epistemic product semantics are minimally necessary so actors act from information they can legitimately know or believe, including ignorance, partial information, stale/false belief and deception, rather than from hidden canonical truth?

The result is research/product guidance for future consumers. It does **not** implement a belief database, perception system, dialogue engine, save format, inference engine, UI, runtime query API or confidence formula.

The central authority invariant is:

```text
canonical world truth != actor-accessible belief

missing actor belief/access -> UNKNOWN
canonical truth mutation -> no automatic actor learning
privileged truth comparison -> debug/test only
```

A later implementation fails PA-04 if an actor becomes epistemically smarter merely because the engine/debugger knows more.

## 2. Canonical Juego2 finding

Knowledge is **actor-local causal state/access**, not a read-through view of canonical simulation truth and not dialogue flavour.

A future consumer needs to distinguish at least these semantic authorities:

```text
CANONICAL WORLD
  what is actually true in the simulation

ACTOR EPISTEMIC STATE
  what actor A currently believes / has legitimately acquired

ACTOR-SAFE QUERY
  what A may use for a decision/dialogue condition

PRIVILEGED TOOLING
  what debug/test may compare against canonical truth
```

The normal actor-facing path is fail-closed:

```text
query(actor A, proposition P)
  -> HELD(value/provenance/age/optional strength)
  -> UNKNOWN

UNKNOWN must not become worldTruth(P)
```

This boundary makes ignorance, secrecy, stale belief, mistaken belief and deception possible without corrupting canonical truth.

## 4. Acquisition and provenance rules

PA-04 adopts conceptual acquisition categories, not final enums or APIs.

### 4.1 `PERCEPTION`

An actor may acquire/revise a belief from a perception path that later implementation explicitly authorizes for that actor.

PA-04 does not choose sight/hearing geometry, sensory ranges or Unity physics. It requires only that perception be a causal acquisition event rather than a disguised global-truth read.

### 4.2 `PUBLIC_SOURCE`

Public does **not** mean ambient omniscience.

A public fact may be obtainable from a noticeboard, schedule, office, newspaper, broadcast, institutional feed or equivalent source, but the actor must actually access it or be covered by an explicit authored distribution rule.

```text
PUBLICLY AVAILABLE != ALREADY KNOWN BY EVERY ACTOR
```

### 4.3 `COMMUNICATION`

A received claim may become a belief input when the receiver accepts/revises from that communication event.

PA-04 owns the receiver epistemic state that results. PA-05 owns why/when a sender communicates, multi-hop propagation, distortion, corroboration and rumour-flow budgets.

### 4.4 `AUTHORED`

Initial conditions or explicit authored knowledge grants are permitted when their origin/access rule is traceable. They may not become an untracked quest/dialogue duplicate of who knows what.

### 4.5 `INFERENCE`

PA-04 does **not** require a generic inference engine.

If later consumers need inference, the minimum safe shape is:

- named rule;
- explicit actor-accessible inputs;
- deterministic/traceable output;
- bounded scope;
- no hidden canonical lookup;
- no recursive/global closure by default;
- no LLM/general reasoner as epistemic authority.

## 5. Minimum belief semantics without freezing a schema

A future representation must be able to preserve the meaning of:

```text
owner actor
proposition / subject-facet key
believed value/state
acquired or revised time
immediate source kind
immediate source/ref when material
optional bounded epistemic strength only if a real consumer exists
```

These are semantic needs, not mandatory field names.

### 5.1 Ignorance

Absence of actor-accessible knowledge is `UNKNOWN`, not `false`.

```text
WorldFact(door_locked) = true
Actor A has no belief/access
=> query(A, door_locked) = UNKNOWN
```

The distinction matters because `false` and `unknown` may legitimately produce different behaviour.

### 5.2 False belief

An actor may hold a value that disagrees with canonical truth. That disagreement is not itself actor-readable.

### 5.3 Stale belief

A belief may remain unchanged after canonical truth changes if no explicit acquisition/revision event reaches the actor.

Truth changes are world causes, not telepathy.

### 5.4 Partial belief

Partial information should be represented at the semantic granularity the gameplay needs rather than by granting the hidden complete fact.

Example:

```text
actor legitimately knows:
  witness_clothing = blue
actor does not know:
  witness_identity
```

The known facet may be queried; the unknown facet remains `UNKNOWN`. PA-04 does not require a probabilistic world model to represent this.

### 5.5 Certainty / epistemic strength

Juego2 does **not** adopt a decorative confidence float as baseline authority.

A bounded certainty/strength band is **conditional**:

- keep it only if at least one real eligibility, ranking, revision, verification or explanation path consumes it;
- explain when it materially affected an outcome;
- otherwise omit it rather than simulate precision with no gameplay consequence.

PA-04 therefore covers uncertainty without freezing probability calculus or Bayesian tuning.

## 6. Truth labels are privileged relations, not actor-owned facts

Actor-facing epistemic state must not contain authoritative fields equivalent to:

```text
isTrue
isFalse
isStale
canonicalValue
canonicalRevision
```

Those labels require comparison with information the actor may not possess.

A debugger/test may derive:

```text
MATCH
MISMATCH
BELIEF_UNKNOWN
WORLD_ABSENT
beliefAge
```

but those outputs are segregated from ordinary actor decision/dialogue inputs.

This closes a subtle omniscience path: an implementation still fails if it never directly calls `WorldFact` but hands the actor a precomputed `isStale=true` flag.

## 7. Revision semantics

Canonical truth change alone does not rewrite actor beliefs.

Allowed revision causes include explicit events such as:

- new legitimate perception;
- consultation of an accessible public source;
- received communication;
- explicit authored correction/grant;
- bounded named inference from actor-accessible inputs.

A future revision policy may consider current belief, new evidence, source semantics, PA-03/05 credibility inputs or a bounded certainty/strength representation. PA-04 does not select the algorithm or numeric weights.

The policy must remain deterministic/explainable enough to answer why the actor retained, replaced or rejected a belief.

## 8. Secrets, concealment and deception

### 8.1 Secrets

A secret is primarily an acquisition/access condition, not a magic global flag that itself tells the engine who knows it.

```text
canonical fact exists
witnesses/authorized sources acquire it through explicit paths
others remain UNKNOWN until they legitimately learn/discover it
```

A `secret` content tag may later help configure access, but the tag cannot substitute for actor-specific acquisition state.

### 8.2 Concealment

Concealment changes the availability/effectiveness of acquisition paths. It does not erase canonical truth and does not require direct mind editing.

Exact stealth/perception mechanics are deferred.

### 8.3 Deception

Deception must be representable as epistemic state, not only rendered text.

Minimal seam:

```text
source communicates claim P=valueX
receiver accepts/revises from the claim
=> receiver may hold P=valueX with COMMUNICATION provenance
```

The canonical truth may disagree.

PA-04 does not decide the sender's motive, opportunity to speak, trust transform, retransmission, distortion, corroboration or cascade. Those belong to PA-05 and other actor-owned systems.

## 9. Shared player/NPC causal city

PA-04 must help gameplay, not merely make background NPC simulation more sophisticated.

### Player-caused information asymmetry

The player may legitimately:

- witness something before others;
- tell one actor but not another;
- reveal or conceal evidence;
- alter access to a public/institutional source;
- create a misleading situation or claim through an owned action path;
- later encounter different actor behaviour because their information states diverged.

Those consequences must enter the same epistemic ownership seams used for NPC-caused information. A privileged `player_revealed_secret=true` flag that directly changes everyone is not the default model.

### Intentional transformation

If sustained player action closes an office, destroys a noticeboard, changes an institution or repeatedly spreads information, the town may develop materially different information distribution.

PA-04 does not protect the starting information equilibrium by auto-resynchronizing beliefs. Normal recovery/information flow may happen only through legitimate later owners/causes.

### Human player knowledge vs player-character/system knowledge

PA-04 does not pretend the human player can be made to forget observed information. It constrains simulation/narrative state that future game systems query. UI/presentation rules for what the human may inspect remain deferred.

## 10. Ownership boundaries

The safe composition is:

```text
world / action / perception / communication owner
        ↓ legitimate acquisition event
PA-04 epistemic owner
        ↓ actor-safe belief query
PA-02 actor-owned decision or authored condition
```

### Ownership matrix

| Concern | PA-04 ownership | Other owner / boundary |
|---|---|---|
| canonical fact itself | not PA-04 | owning world/system domain |
| actor belief/access to proposition | **PA-04 semantic ownership** | final H4 runtime representation deferred |
| private belief about PA-03 relationship | **PA-04 owns belief/access** | PA-03 owns canonical relationship state |
| sender motive/opportunity to communicate | not PA-04 | PA-02/PA-05/action owner |
| multi-hop rumour propagation/distortion/corroboration | not PA-04 | **PA-05** |
| autobiographical event memory/salience/forgetting/compaction | not PA-04 | **PA-06** |
| source trust/relationship state | may be an input | PA-03/PA-05 own semantics/use at their boundary |
| work/activity/governance facts | may be propositions actors know/believe | PA-07/08/12 own those canonical domains |
| player causal action that creates an information event | PA-04 consumes resulting acquisition where appropriate | PA-09 owns generic player-action semantics |
| final persistence/save format/query API/performance | no final PA-04 ownership | future H4/runtime consumer |

Boundary invariant:

```text
WorldEvent / canonical fact
    != ActorBelief
    != RumourTransmission
    != AutobiographicalMemory
```

One event may create records/effects in several domains, but none substitutes for another.

## 12. Required causal fixtures

These are research acceptance fixtures, not claims that runtime code exists.

### CF-01 — Same world, different belief => required different decision

Purpose: satisfy the PA-04 central acceptance with a falsable A/B outcome rather than merely saying knowledge “may” matter.

Fixed comparison surface:

```text
canonical world = W
actor role/needs/routine = fixed
relationships = fixed
physical opportunity surface = fixed
seed/tie conditions = fixed
actor-owned goal = ATTEND_SCHEDULED_MEETING
eligible semantic actions = [TRAVEL_TO_TOWN_HALL, SEEK_MEETING_INFORMATION]
all non-epistemic inputs = fixed
```

RUN A — Antonio:

```text
belief meeting_location = town_hall
provenance = PUBLIC_SOURCE
source = consulted_meeting_notice
```

Required result:

```text
selected semantic action = TRAVEL_TO_TOWN_HALL
explanation names held meeting_location belief + provenance
```

RUN B — Manolo:

```text
meeting_location = UNKNOWN
no perception / communication / accessed source / authored grant
```

Required result:

```text
selected semantic action = SEEK_MEETING_INFORMATION
explanation names UNKNOWN as the gating difference
```

The fixture **FAILS** if:

- both runs produce the same material action;
- canonical truth is consulted to make Manolo travel directly;
- a relationship/routine/opportunity/seed difference is required to obtain the flip;
- a hidden tie-break rather than the epistemic difference explains the result.

PA-02 retains ownership of the general chooser. This fixture only proves the PA-04-owned epistemic input can causally change a fixed actor-owned decision surface.

### CF-02 — Stale belief survives hidden truth change

Fixed:

```text
actor = Carmen
actor belief shop_open = true from T1 perception
actor has received no later acquisition/revision event
semantic decision surface = GO_TO_SHOP vs SEEK_ALTERNATIVE
all actor-visible inputs fixed
```

RUN A canonical truth at T2:

```text
shop_open = true
```

RUN B canonical truth at T2:

```text
shop_open = false
```

Required actor-safe input in both runs:

```text
HELD(shop_open=true, acquiredAt=T1)
```

Required decision in both runs at the belief-gated stage:

```text
GO_TO_SHOP
```

Privileged tooling may report `MATCH` in A and `MISMATCH` in B. The actor path must not consume that difference.

The fixture **FAILS** if the canonical truth mutation silently repairs Carmen's belief or changes the actor-safe query without an acquisition event.

### CF-03 — Accepted deceptive claim changes receiver epistemic state

Input seam is intentionally exogenous to PA-04 sender logic:

```text
canonical alibi_valid = false
receiver = Paco
Paco initially has alibi_valid = UNKNOWN
communication event arrives from Carmen asserting alibi_valid = true
fixture declares receiver accepts/revises from that claim
```

Required result:

```text
Paco belief alibi_valid = true
sourceKind = COMMUNICATION
sourceRef = Carmen
```

A later Paco decision that declares this proposition relevant may consume the false belief. The fixture does not specify why Carmen lied, whether Paco retransmits, or how rumours mutate.

The fixture **FAILS** if the lie exists only as dialogue text while Paco's epistemic state remains canonical/unchanged.

## 13. Negative controls

### NC-01 — No omniscient fallback

```text
WorldFact mayor_murdered = true
Paco has no belief/access path
```

Required:

```text
query(Paco, mayor_murdered) = UNKNOWN
```

Any fallback to canonical truth is a PA-04 failure.

### NC-02 — Hidden/debug truth metadata cannot change actor input

Fixed actor belief and every actor-visible input. Change only privileged diagnostic metadata derived outside the actor-safe surface, for example `MATCH -> MISMATCH` or canonical revision/age annotations not legitimately acquired by the actor.

Required:

```text
actor-safe query result unchanged
belief-gated decision input unchanged
material decision unchanged unless another legitimate world/opportunity input independently changes
```

If the diagnostic relation changes actor behaviour, privileged truth has leaked.

### NC-03 — Public does not mean ambient

A noticeboard contains `festival_cancelled=true`, but Actor A has not consulted it and has no authored distribution rule that delivers it.

Required:

```text
query(A, festival_cancelled) = UNKNOWN
```

The fact's public availability does not by itself preload A's belief.

### NC-04 — PA-03 private relationship truth remains non-ambient

Canonical state contains:

```text
trust(Carmen -> Paco) = LOW
```

Antonio has no legitimate acquisition path for that private third-party relation.

Required:

```text
Antonio belief/query about trust(Carmen -> Paco) = UNKNOWN
```

PA-04 may later represent a belief/claim about the relationship, including a wrong one, without rewriting PA-03 truth.

### NC-05 — Partial knowledge does not reveal the hidden whole

Actor legitimately knows `witness_clothing=blue` but not `witness_identity`.

Required:

```text
query(witness_clothing) = HELD(blue)
query(witness_identity) = UNKNOWN
```

A convenience object that exposes the complete hidden witness record through the known facet fails the boundary.

### NC-06 — Bounded lookup remains inherited

A future knowledge-backed target/action source may use actor-local/indexed state, but it must not begin with `all actors/all facts -> filter what this actor knows` as the normal semantic discovery path.

This control consumes accepted PA-02/03 bounded-discovery authority; PA-04 does not select the final index.

## 14. Explanation minimum

When epistemic state materially changes a decision, a future explanation surface should be able to identify conceptually:

```text
decision owner
semantic action/target/condition
proposition/facet queried
query result: HELD | UNKNOWN
held value when present
immediate source kind/ref when material
acquired/revised time when material
optional certainty/strength only when actually consumed
reason the condition passed/failed or the action changed
```

Privileged debug may additionally show canonical comparison, but actor-facing reasoning must be clearly distinguishable from that diagnostic view.

The explanation requirement is semantic, not a final UI/log format.

## 15. Future H4 consumer notes

A later Living World Core consumer should preserve these constraints while choosing actual runtime representation:

1. **Separate authorities.** World truth and actor epistemic state may share identifiers but may not collapse into one read-through store.
2. **One actor-safe query seam.** Behaviour/dialogue/conditions should consult compatible epistemic state rather than independent `knows_X` copies.
3. **Fail closed.** Missing state remains `UNKNOWN` unless an explicit mechanic owns omniscient access.
4. **Persist false/stale state directly.** Save/load/replay must not silently reconstruct beliefs from current truth.
5. **Bound lookup.** Normal queries should be indexed/scoped by actor + relevant proposition/facet or an equivalent bounded source.
6. **Keep debug privileged.** Truth comparison/redaction/debug helpers must not be callable as normal decision inputs by accident.
7. **Keep provenance compact.** PA-04 needs immediate causal origin; PA-05/06 own longer transmission/history questions.
8. **Instrument leakage tests.** Future runtime proof should include negative fixtures where canonical/debug truth changes while actor-visible state is fixed.
9. **Share player/NPC semantics where applicable.** Player-caused information events should enter normal causal paths rather than a privileged quest-only knowledge universe.
10. **Do not overbuild inference.** Start with explicit acquisition and simple authored conditions; add inference only from demonstrated gameplay need.

## 19. Result

Juego2 should **ADOPT** the strict epistemic authority boundary:

```text
canonical truth
    !=
actor-accessible belief
```

and the associated fail-closed rules:

- missing knowledge is `UNKNOWN`;
- acquisition/revision requires a legitimate causal path;
- false/stale belief may persist;
- immediate provenance is compact and explainable;
- actor-safe queries cannot consume privileged truth comparisons;
- deception can create receiver epistemic state;
- partial knowledge does not reveal hidden complete state;
- public availability is not automatic knowledge;
- player and NPC information consequences belong to the same causal city.

Juego2 should **ADAPT conditionally** certainty/strength and bounded inference only when a concrete consumer demonstrates value.

Juego2 should **DEFER** PA-05 rumour dynamics, PA-06 autobiographical memory, exact perception/dialogue/runtime schemas, tuning, persistence implementation and performance proof.

Juego2 should **REJECT for baseline** omniscient fallbacks, automatic truth synchronization, actor-visible truth/stale labels, duplicate `knows_X` authorities, unbounded provenance, global scans, general recursive Theory of Mind and LLM/general-reasoner epistemic authority.

The product payoff is concrete: two people can inhabit the same town, know different things, make different correct-for-them decisions, be wrong for understandable reasons, and later learn differently—without the simulation cheating by telling them what only the engine knows.
