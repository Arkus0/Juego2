## 0. Question and recommendation

PA-08 asks:

> What minimal shared activity model lets NPCs and the player participate in leisure/social activities as ordinary town life, while preserving schedule, capacity, agency and consequence ownership and keeping each minigame independently fun?

**Recommendation:** adopt a **thin shared activity integration seam**, not a universal minigame engine.

```text
activity opportunity
(place + availability + capacity + participant requirements)
        ↓
PA-02 actor chooses whether/how to participate
        ↓
activity session owns only its local game/session state
        ↓
activity-specific rules resolve
        ↓
small structured activity outcome
        ↓
normal owners decide whether anything later matters
(schedule/material/relationship/belief/communication/memory/event)
```

The critical distinction is:

> **The minigame owns play. The Living World owns context and aftermath.**

An activity counts as Living World integrated only if it can exist in ordinary town life without player activation where appropriate, consumes real opportunity, and can emit bounded consequences through existing owners. A polished private score screen is not sufficient.

## 2. Minimal shared activity vocabulary

These are semantic responsibilities, not frozen runtime types/APIs.

### 2.1 Activity opportunity

A discoverable opportunity needs only the facts relevant to participation:

- activity identity/family;
- real place/POI;
- current availability/window/condition;
- participant requirements where necessary;
- finite capacity/reservable slots where contention matters;
- expected time/opportunity cost;
- optional agreed stake/material requirement;
- initiation modes such as self-join, invitation, challenge or companion participation.

The opportunity does not choose a participant. PA-02 does.

### 2.2 Activity session

Once participation begins, a session may temporarily own:

- current participants/roles/teams;
- reserved activity-specific slots/resources;
- start/progress/end state;
- activity-local rules and score/state;
- explicit interruption disposition: cancel, settle/forfeit, or pause/resume only where genuinely supported.

It must not become a second schedule, relationship, belief or memory system.

### 2.3 Structured activity outcome

Only state useful outside the activity crosses the boundary. Candidate semantic fields are:

```text
activity/session identity
participants and roles actually involved
place + start/end/duration
completed/cancelled/forfeited/paused outcome
winner/loser/rank only where meaningful
agreed stake settled/unsettled where meaningful
material output where meaningful
notable conduct only if semantically justified
observable/witness context
```

Internal score, controls, animation beats and game tactics remain local unless a downstream owner has a concrete reason to consume them.

### 2.4 Activity integration profile

A content author should eventually be able to answer:

- Why is this fun as a game?
- Where/when can it exist?
- Can NPCs initiate/use it without the player?
- Who can join/refuse/watch/leave?
- What capacity/resource does it consume?
- What interrupts it and how does it recover?
- What small outcome crosses into the Living World?
- What stays activity-local?

This is a content/design contract, not a universal runtime framework.

## 4. Social probe — mus/cards at Bar F01

This is an integration probe, not a shipping commitment or card-rules design.

```text
Name: Bar cards / mus probe
Town role: recurring social leisure
Location: Bar F01 / compatible table opportunity
Availability: venue open + usable table + enough eligible participants
NPC autonomous participation: YES, conditional on PA-02 choice
Initiation: spontaneous opportunity / invitation / challenge
Capacity: finite table/participant slots
Time cost: real causal time
Player join: may join an existing compatible session; arrival does not reset NPC context
Spectator: optional if physical/content design supports it
Stakes: NONE by default; optional bounded agreed stake if later justified
Boundary outcome: participation, completion, relevant team/result, duration, settlement, notable observed conduct
Witness facts: only participants/actual observers/legitimate later reports

Interruption: closing/departure/priority -> explicit settle/forfeit/cancel rule
What stays local: cards, hand state, scoring procedure, AI game tactics, control/UI
Disposition: ADOPT as H3/H4 integration benchmark; minigame mechanics LATER
```

Antonio and Manolo can form/enter a session while the player is elsewhere if venue/table/time and their own decisions permit it. The player may later join if a valid slot/transition permits; joining must not reset existing participants/history merely to center the protagonist.

## 5. Individual / low-social probe — fishing

Fishing prevents PA-08 from becoming only a bar/group-game contract.

```text
Town role: quiet individual or companion leisure
Location: accepted fishing opportunity/spot
Availability: place + condition/window if content needs one
NPC autonomous participation: YES where actor routine/choice supports it
Capacity: only if useful spots are intentionally scarce
Time cost: real
Player join: independent nearby use or companion participation depending content
Boundary outcome: duration, catch/material result only if PA-07 says it matters, optional shared experience
Witness facts: nearby participant/observer only
Interruption: leave, schedule conflict, invalid place/condition
What stays local: cast/input/fish mechanics/skill expression
Disposition: ADOPT as contrasting research profile; actual fishing game LATER
```

A catch does not automatically become economy, memory or rumour. If it changes no downstream owner, it can remain transient activity-local output.

## 6. Participation, capacity and interruption

Joining/refusing/watching/leaving is actor-owned whenever it represents a meaningful choice. The activity states eligibility and available modes; PA-02 owns the response.

Capacity matters only where contention is understandable: table full, useful spot occupied, equipment unavailable, or venue/service degraded. A rejected/waiting actor returns to a bounded PA-02 alternative rather than globally scanning every activity in town.

Every adopted activity class needs an explicit semantic interruption disposition. Slots/resources are released coherently and actors re-enter current-context routine/decision flow. “Player walked away and the activity vanished with no cleanup” is not acceptable.

## 7. Structured outcomes, salience and repetition

Most ordinary sessions should die as ordinary state. A structured outcome is **eligible input**, not guaranteed durable history:

- PA-03 decides whether a socially meaningful result changes relationship state;
- PA-04/05 decide legitimate knowledge/communication;
- PA-06 decides bounded memory selection;
- PA-07 decides whether a material output/stake affects material state;
- future PA-10 may consume an outcome in an autonomous event chain.

Repeated low-stakes play must not create one durable memory/event/rumour per session.

A valid positive/neutral causal chain is, for example:

```text
Antonio chooses cards
 -> invites Manolo
 -> Manolo accepts via PA-02
 -> session consumes real time/table capacity
 -> they finish later than Antonio's expected leisure window
 -> PA-01/02 re-evaluate current context
 -> a later social/work opportunity differs
```

No scandal or combat is required for systemic consequence.

## 8. Mechanism decisions

| Mechanism | Disposition | Reason |
|---|---|---|
| Opportunity separate from local game rules | **ADOPT** | Lets routine/agency discover play without universalizing mechanics. |
| NPC participation without player | **ADOPT** | Prevents an activity-prompt world. |
| Real place/time/capacity where causal | **ADOPT** | Connects leisure to ordinary life. |
| Small structured outcome boundary | **ADOPT** | Enables downstream composition without ownership theft. |
| Explicit interruption disposition | **ADOPT** | Prevents stranded slots/schedules. |
| Social + low-social profiles | **ADOPT** | Avoids designing only for group bar games. |
| Player uses the same opportunity/session seam | **ADOPT** | Supports PA-09 shared causality. |
| Every session becomes event/rumour/memory | **REJECT** | Violates salience/boundedness. |
| Minigame directly updates relationship/belief/schedule | **REJECT** | Duplicate authority. |
| Universal framework for every internal minigame rule | **REJECT** | Integration seam must be smaller than mechanics. |
| Living World hooks as proof a weak game is fun | **REJECT** | Systemic richness cannot rescue poor play. |
| Exact UI/input/animation/game AI/rules | **LATER** | Requires playable implementation and human evaluation. |

## 11. Unit conclusion

PA-08 recommends **fewer, stronger activities** that are real town opportunities first and minigames second.

The test is deliberately two-sided:

> If the player never approaches, can this activity still belong to the town where appropriate? And if all Living World hooks are removed, is the player-facing game still worth playing?

The first answer is the integration requirement. The second is a later playable-quality requirement. Neither substitutes for the other.
