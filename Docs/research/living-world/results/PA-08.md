## 0. Question and recommendation

PA-08 asks:

> What minimal shared activity model lets NPCs and the player participate in leisure/social activities as ordinary town life, while preserving schedule, capacity, agency and consequence ownership and keeping each minigame independently fun?

**Recommendation:** adopt a **thin shared activity integration seam**, not a universal minigame engine.

```text
activity opportunity
(place + availability + capacity + participant requirements)
        ↓
PA-02 actor chooses whether/how to participate
        ↓
activity session owns only its local game/session state
        ↓
activity-specific rules resolve
        ↓
small structured activity outcome
        ↓
normal owners decide whether anything later matters
(schedule/material/relationship/belief/communication/memory/event)
```

The critical distinction is:

> **The minigame owns play. The Living World owns context and aftermath.**

An activity counts as Living World integrated only if it can exist in ordinary town life without player activation where appropriate, consumes real opportunity, and can emit bounded consequences through existing owners. A polished private score screen is not sufficient.

## 2. Minimal shared activity vocabulary

These are semantic responsibilities, not frozen types/APIs.

### 2.1 Activity opportunity

A discoverable opportunity should be describable by the minimum facts relevant to participation:

- activity identity/family;
- real place/POI;
- current availability/window/condition;
- participant requirements where necessary;
- finite capacity/reservable slots where contention matters;
- expected time/opportunity cost;
- optional agreed stake/material requirement;
- initiation modes such as self-join, invitation, challenge or companion participation.

The opportunity does not choose a participant. PA-02 does.

### 2.2 Activity session

Once participation begins, a session may temporarily own:

- current participants/roles/teams;
- reserved activity-specific slots/resources;
- start/progress/end state;
- activity-local rules and score/state;
- explicit interruption disposition: cancel, settle, forfeit, pause/resume where that activity supports it.

It must not become a second general schedule, relationship, belief or memory system.

### 2.3 Structured activity outcome

Only state useful outside the activity crosses the boundary. Candidate semantic fields:

```text
activity identity / session identity
participants and roles actually involved
place + start/end/duration
completed / cancelled / forfeited / paused outcome
winner/loser/rank only where meaningful
agreed stake settled/unsettled where meaningful
material output where meaningful
notable conduct only if semantically justified by the activity
observable/witness context
```

Every internal score, animation beat or control event stays local unless a downstream owner has a concrete reason to consume it.

### 2.4 Activity integration profile

A content author should eventually be able to answer, without inventing new systems per minigame:

- Why is this fun as a game?
- Where/when can it exist?
- Can NPCs initiate/use it without the player?
- Who can join/refuse/watch/leave?
- What capacity/resource does it consume?
- What interrupts it and how does it recover?
- What small outcome crosses into the Living World?
- What must remain activity-local?

This profile is a content/design contract, not a universal runtime framework.

## 4. Social probe — mus/cards at Bar F01

This is an integration probe, not a shipping commitment or card-rules design.

### Why it is strong

- naturally social;
- real table/seat capacity;
- partners/opponents/invitations;
- time cost and closing time;
- ordinary bar context;
- possible modest stake without requiring a gambling economy;
- observers/conversation can exist;
- easy NPC-only plausibility;
- result can matter later without requiring persistent “mus level” state.

### Integration profile

```text
Name: Bar cards / mus probe
Town role: recurring social leisure
Location: Bar F01 / compatible table opportunity
Availability: venue open + usable table + enough eligible participants
NPC autonomous participation: YES, conditional on PA-02 choice
Initiation: spontaneous opportunity / invitation / challenge
Capacity: finite table/participant slots
Time cost: real causal time
Player join: may join an existing compatible session; arrival does not reset NPC context
Spectator: optional, only if physical/content design supports it
Stakes: NONE by default; optional bounded agreed stake if later justified
Boundary outcome: participation, completion, relevant team/result, duration, settlement, notable observed conduct
Witness facts: only participants/actual observers/legitimate later reports
Schedule consequence: time consumed; late/aborted next intent is handled by PA-01/02
Interruption: closing/departure/priority -> explicit settle/forfeit/cancel rule
What stays local: cards, hand state, scoring procedure, AI game tactics, control/UI
Disposition: ADOPT as H3/H4 integration benchmark; minigame mechanics LATER
```

### NPC-only case

Antonio and Manolo can form/enter a session while the player is elsewhere if the venue/table/time and their own decisions allow it. This is required to prove that Bar F01 is not a dormant minigame portal.

### Player joins existing case

The player may later join if a slot/transition rule permits. Joining does not erase the session's current participants/history merely to create a protagonist-centered fresh instance.

## 5. Individual / low-social probe — fishing

Fishing is the useful contrast because activity integration must not mean “bar group game.”

```text
Town role: quiet individual or companion leisure
Location: accepted fishing opportunity/spot
Availability: place + condition/window if content needs one
NPC autonomous participation: YES where actor routine/choice supports it
Capacity: only if useful spots are intentionally scarce
Time cost: real
Player join: independent nearby use or companion participation depending content
Boundary outcome: duration, catch/material result only if PA-07 says it matters, optional shared experience
Witness facts: nearby participant/observer only
Interruption: leave, schedule conflict, invalid place/condition
What stays local: cast/input/fish mechanics/skill expression
Disposition: ADOPT as contrasting research profile; actual fishing game LATER
```

A catch need not automatically become economy, memory or rumour. If it changes no later owner, it can remain transient activity-local output.

## 6. Participation, capacity and interruption findings

### Participation

Joining/refusing/watching/leaving is actor-owned whenever it represents a meaningful choice. The activity can state eligibility and available modes; it cannot read all social internals and synthesize the actor's answer itself.

### Capacity

Capacity is valuable when it creates understandable contention:

- table full;
- useful spot occupied;
- equipment unavailable;
- venue/service closed or degraded.

Rejected/waiting actors return to PA-02 for another valid action rather than thrashing or globally scanning every activity in town.

### Interruption

Every adopted activity class needs an explicit semantic answer for what happens when continuation becomes invalid:

- `CANCEL`;
- `FORFEIT/SETTLE_EARLY`;
- `PAUSE_RESUME` only where genuinely useful;
- participants/slots are released coherently;
- actors re-enter current-context decision/routine flow.

“Player walked away and the activity vanished with no state cleanup” is not acceptable.

## 7. Structured outcomes, salience and repetition

Most ordinary sessions should die as ordinary state.

A structured outcome is **eligible input**, not guaranteed durable history. Downstream owners decide:

- PA-03: whether a socially meaningful result affects current relationship state;
- PA-04/05: who legitimately knows or later hears about it;
- PA-06: whether the experience is selected under bounded memory policy;
- PA-07: whether a material output/settled stake changes relevant material state;
- future PA-10: whether a result contributes to an autonomous event chain.

Repeated low-stakes play must not produce one durable memory/event/rumour per session. Repetition may instead remain transient or later become a bounded pattern through the relevant owner.

## 8. Positive/neutral causal chain

A qualifying chain does not require cheating, fighting or scandal:

```text
Antonio chooses a card session
 -> invites Manolo
 -> Manolo accepts through his own PA-02 response
 -> session consumes real time and table capacity
 -> they finish later than Antonio's expected leisure window
 -> Antonio's next actual routine is re-evaluated
 -> a later social/work opportunity differs
```

Or:

```text
Antonio invites player to fish
 -> player accepts
 -> both spend real time at the fishing place
 -> another actor who actually sees them together may acquire that fact
 -> later invitation/opportunity may differ through normal owners
```

The activity creates a shared situation. It does not own the later relationship/belief/action.

## 9. Mechanism decisions

| Mechanism | Disposition | Reason |
|---|---|---|
| Activity opportunity separate from session rules | **ADOPT** | Lets schedule/agency discover play without universalizing mechanics. |
| NPC participation without player for ordinary-town activities | **ADOPT** | Prevents activity-prompt world. |
| Real place/time/capacity | **ADOPT where causally useful** | Connects leisure to daily life. |
| Small structured outcome boundary | **ADOPT** | Allows downstream composition without direct cross-owner mutation. |
| Explicit interruption disposition | **ADOPT** | Prevents stranded reservations/schedules. |
| Social and low-social activity profiles | **ADOPT** | Avoids designing integration only around group bar games. |
| Player may join/interfere through same opportunity/session seam | **ADOPT** | Prepares PA-09 shared causal world. |
| Every session becomes event/rumour/memory | **REJECT** | Violates salience/boundedness. |
| Minigame directly updates relationships/beliefs/schedule | **REJECT** | Duplicate authority. |
| One universal framework for every internal minigame rule | **REJECT** | Integration seam should be smaller than game mechanics. |
| Living World hooks as proof that weak mechanics are fun | **REJECT** | Systemic richness cannot rescue poor play. |
| Exact UI/input/animation/game AI/rules | **LATER** | Needs playable implementation and direct human evaluation. |

## 10. Acceptance scenarios disposition

The frozen A07B-1..12 set is represented in the batch fixtures. Research conclusions are:

- **A07B-1 NPC-only:** supported by opportunity + PA-02 participation.
- **A07B-2 player joins existing:** supported without resetting session context.
- **A07B-3 relationship affects participation, not rules:** owner boundary preserved.
- **A07B-4 outcome feeds later decision:** structured outcome is routed through owner, not quest flag.
- **A07B-5 non-witness ignorance:** PA-04/05 inherited guarantee applies.
- **A07B-6 interruption:** explicit disposition + release/re-evaluate.
- **A07B-7 capacity:** finite slots produce failure/wait/alternate action without double occupancy.
- **A07B-8 positive causality:** explicit non-conflict chain above.
- **A07B-9 no consequence explosion:** salience/PA-06 bounds preserved.
- **A07B-10 minigame island:** hard negative, rejected.
- **A07B-11 no-fun rescue:** retained as mandatory later playable gate; research cannot prove fun.
- **A07B-12 quiet-town compatibility:** ordinary sessions remain ordinary unless a legitimate cause raises salience.

## 11. Hard negatives

### Minigame island

A polished activity with a private score/reward that:

- exists only after player prompt;
- ignores venue/time/capacity;
- has no NPC participation;
- produces no bounded shared outcome;

**fails PA-08 regardless of production quality.**

### Integration theatre

An activity that writes `relationship += 5`, `memory = wonGame`, or `schedule = late` directly is also rejected. It may look integrated, but it steals downstream ownership rather than composing with it.

### Fun false positive

PA-08 research can say an activity is structurally integrated. It cannot declare it fun. A future playable activity that fails bounded human play inspection remains a product reject even if every systemic seam is correct.

## 13. Unit conclusion

PA-08 recommends **fewer, stronger activities** that are real town opportunities first and minigames second.

The test is deliberately two-sided:

> If the player never approaches, can this activity still belong to the town where appropriate? And if all Living World hooks are removed, is the player-facing game still worth playing?

The first answer is the integration requirement. The second is a later playable-quality requirement. Neither substitutes for the other.
