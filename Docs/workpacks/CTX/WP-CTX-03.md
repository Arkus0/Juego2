# WP-CTX-03 — Structured evidence, DocSync and history separation

Status: **FROZEN PLAN / NOT_STARTED**
Class: **PROCESS_ONLY / NON-PRODUCT-FOUNDATIONAL**
Execution: **REMOTE_OK**
Depends on: `WP-CTX-02` PASS + merge + DocSync
Blocks: none

## Objective

Remove repeated state/proof/history prose from normal agent attention, make DocSync/state drift easier to detect mechanically, and close the CTX programme with measured before/after context quality.

## Required inputs

- accepted CTX-01 role/bootstrap authority rules;
- accepted CTX-02 contract-capsule rules;
- current proof/residual matrices, PR handoff conventions, ROADMAP history and DocSync flow;
- representative H1/CITY/PA session measurements.

## Work

- introduce structured representations for naturally tabular evidence such as proof obligations, negative controls, residual rows, accepted SHAs and durable state;
- keep causal explanation in prose where reasoning itself is evidence;
- compact PR handoff bodies to state/scope/freeze/findings/pointers instead of duplicating full evidence;
- separate current ROADMAP/gate planning from long accepted closure narrative while preserving exact history/provenance under `Docs/history/` or equivalent;
- make DocSync update one compact derived accepted-state/index surface plus only affected authoritative docs rather than manually restating the same fact broadly;
- add stale/consistency checks where practical;
- measure representative bootstrap/context cost before and after CTX using Worker PA, Worker H1, blocked CITY and Reviewer roles;
- record whether any FAIL/review quality signal regressed during the CTX rollout.

## Forbidden

- no deletion of accepted evidence for token savings;
- no conversion of causal reasoning into opaque tables when prose is needed to understand why proof is valid;
- no single generated file may become semantic authority merely because it is easy to parse;
- no retroactive bulk rewrite of every H0 artefact unless required by a live consumer or consistency check;
- no product/runtime change.

## Required controls

- a stale structured row/index cannot override live GitHub or exact accepted evidence;
- deleting one required proof/residual reference from a structured registry is detected or forces deeper reconstruction rather than producing a false complete view;
- ROADMAP-history separation preserves every accepted milestone/gate pointer needed to reconstruct past closure;
- compact PR handoff still lets a fresh Reviewer locate complete candidate evidence and full diff without private chat context;
- DocSync on a representative accepted transition updates the compact state once and does not leave contradictory next-WP state in normal bootstrap surfaces.

## Acceptance

Compared with the pre-CTX baseline, representative fresh sessions load materially less irrelevant history/duplicated state before claim analysis while preserving all required semantic/proof sources, independent review behavior and reconstruction paths. Any remaining duplication is classified as intentional authority, causal narrative, or future residual rather than accidental repetition.

## Definition of Done

The three-WP CTX programme has independently reviewed role routing, safe predecessor compression, structured evidence/state/history handling, and measured closure. No additional CTX gate is required unless CTX-03 evidence itself reveals an unresolved process-quality defect.
