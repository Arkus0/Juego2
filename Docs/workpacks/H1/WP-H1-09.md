## Architecture / authority boundary

Canonical -> Unity is authoritative. Unity -> canonical is a proposal. A proposal is stale-aware and gains provenance only if the ordinary H0 mutation authority accepts it. Catalogue drift cannot be “fixed” by rewriting the canonical selection silently.

## Acceptance criteria

- effective managed drift is complete for the accepted H1 units and deterministically ordered;
- unrelated unmanaged objects are visible/classified without contaminating the managed digest;
- rematerialization restores parity without canonical change;
- a supported Transform/component edit compiles to the expected canonical extension operation/dependencies;
- proposal plan/dry-run is inspectable and a stale base returns accepted HK08B recovery rather than overwrite;
- unsupported, ambiguous or source-asset edits produce stable diagnostics and no proposal;
