## Objective and central claim

Compare expected projection with effective Unity state, classify drift deterministically, rematerialize canonical truth, and translate only supported managed Unity edits into explicit canonical mutation proposals that still require ordinary H0 commit authority.

## WHY_THIS_BOUNDARY

Validation answers whether state is acceptable; reconciliation answers which authority may change which side. That direction can be wrong even with perfect diagnostics. Observation, drift classification and proposal compilation stay together because they form one sync-authority claim; committing proposals stays outside because H0 already owns it.

## Forbidden scope

Silent auto-pull, direct canonical mutation, dual-master last-writer-wins, import of arbitrary unmanaged projects/scenes, merge of independent histories, background watcher service or gameplay state capture.

## Architecture / authority boundary

Canonical -> Unity is authoritative. Unity -> canonical is a proposal. A proposal is stale-aware and gains provenance only if the ordinary H0 mutation authority accepts it. Catalogue drift cannot be “fixed” by rewriting the canonical selection silently.

## Acceptance criteria

- effective managed drift is complete for the accepted H1 units and deterministically ordered;
- unrelated unmanaged objects are visible/classified without contaminating the managed digest;
- rematerialization restores parity without canonical change;
- a supported Transform/component edit compiles to the expected canonical extension operation/dependencies;
- proposal plan/dry-run is inspectable and a stale base returns accepted HK08B recovery rather than overwrite;
- unsupported, ambiguous or source-asset edits produce stable diagnostics and no proposal;
- importing then committing through H0 and rematerializing converges to parity with truthful H0 provenance.

## Deterministic proof / evidence

Start from an in-sync market slice; inject missing object, extra managed marker, changed transform/component, catalogue removal and unmanaged object. Compare exact drift classes. Compile one supported edit, force staleness, recover/replan, commit through H0 and rematerialize.

- unmanaged change silently adopted;
- import proposal mutates canonical state before apply;
- wrong base anchor permits overwrite;
- derived dependency lost on reverse compile;
- catalogue drift rewritten as canonical change;
- rematerialization reports parity while effective observation differs.
