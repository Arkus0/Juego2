# WP-H1-10 — Project checkpoint + clean Unity reconstruction

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: HYBRID
Depends on: `WP-H1-09` PASS
Blocks: `WP-H1-11`

## Objective and central claim

Persist a bounded project checkpoint made from accepted canonical artifacts plus versioned bridge/catalogue metadata, then reconstruct the same canonical state and normalized Unity projection in a fresh process/clean generated-output state without redefining snapshot, replay or lineage semantics.

## WHY_THIS_BOUNDARY

Single-session parity can pass while restart/reconstruction is false. Checkpoint authority and recovery have a different failure model from reconciliation, but snapshot import/replay plus Unity rebuild are inseparable parts of the same project-continuity claim. General durability would be a separate future WP.

## Inherited guarantees

HK06B snapshot/rebase, HK06C replay, HK09B process-local publication boundaries, H1 generation receipts, catalogue fingerprints and reconciliation, including the accepted H1-04 Quaternius Source baseline carried through H1-05..09.

## New guarantees owned

- versioned project-checkpoint manifest referencing canonical snapshot/journal as accepted artifacts;
- fixed project-local atomic checkpoint publication at the claimed level;
- clean-process canonical restore through accepted import/replay only;
- versioned public composed project-checkpoint and clean-rebuild capabilities, with Editor-bound checkpoint/rebuild phases using the H1-03A lifecycle;
- deletion of generated Unity output followed by deterministic rebuild;
- stale/incompatible editor/package/catalogue/binding/source fingerprints fail visibly.

## Explicitly not re-proved

Snapshot/replay semantics generally, H1-04 source adoption/legal approval, WAL/fsync/power-loss durability, distributed storage, cross-version migration or shipping backup policy.

## Allowed scope

Project workspace checkpoint manifest/storage under fixed root, accepted canonical artifact packaging, restart/rebuild orchestration, remote H0 plus local Unity evidence. The rebuild consumes the accepted Quaternius Source baseline as an external project input and verifies the source/catalogue fingerprint required by the checkpoint.

## Forbidden scope

New canonical persisted-world format, fabricated journal history, merging lineages, treating generated Unity assets or source art as recovery authority, cloud sync/database, runtime save state, gameplay, or replacing accepted Quaternius production content with local substitute art merely to make reconstruction easier.

## Architecture / authority boundary

The checkpoint points to/verifies accepted canonical artifacts and bridge inputs. A fresh authored session begins according to existing snapshot import/rebase or replay contracts. Unity is rebuilt afterward and cannot repair missing/corrupt canonical evidence. Quaternius source content is a checksummed/versioned external bridge input: required for faithful projection where referenced, but never canonical recovery truth.

## Acceptance criteria

- checkpoint includes checksummed/versioned canonical artifact, bridge/profile, catalogue, accepted source-content and package/editor fingerprints;
- interrupted/invalid checkpoint does not replace the last accepted checkpoint or claim success;
- fresh process restores canonical hash/revision under truthful existing lineage semantics;
- no generated Unity scene/prefab is needed to recover canonical truth;
- clean generated-output rebuild produces the same normalized plan/observation digest;
- incompatible/missing catalogue, accepted source content or toolchain produces a structured blocked-rebuild state, not silent drift or substitute content;
- H0 diff/provenance/replay evidence remains identical/truthful after the scenario;
- reference and MCP discover and invoke the same checkpoint/rebuild handlers from composition; neither transport uses a private restore script or direct Editor call.

## Deterministic proof / evidence

Remote proof validates canonical artifacts/checkpoint framing; local proof closes editor, removes all generated outputs, opens a fresh project process, restores and rebuilds using the same accepted Quaternius Source baseline. Inject interruption immediately before checkpoint publication and before generation publication; also prove that missing/rebound required source content blocks truthful reconstruction instead of falling back to placeholders.

## Causal negative-conformance classes

- Unity artifact used as canonical recovery source;
- snapshot/journal version or checksum ignored;
- partial checkpoint becomes current;
- imported lineage falsely presented as mutation history;
- generated outputs survive as hidden required state;
- incompatible catalogue/toolchain silently accepted;
- missing/rebound accepted Quaternius source silently replaced by placeholder/substitute art;
- rebuild observation differs while receipt says parity;
- Gate-required checkpoint/rebuild exists only as a test helper, menu item or direct batch script outside public composition.

## Content-shape probe

Do not defer real third-party game-art participation to H1-11; H1-11 expands the breadth and end-to-end shape coverage of the existing source baseline.

## Dependency / IP implications

Checkpoint records dependency identities/versions and the accepted Quaternius Source fingerprint/distribution boundary but does not redistribute editor binaries or source archives contrary to their terms. This WP adopts no competing art dependency.

## Residual risks

No power-loss theorem, remote backup, cross-machine asset-cache portability, cross-Unity-version migration, full Quaternius source breadth or runtime save continuity.

## Exact predecessor reopen condition

HK06B/HK06C reopen only if effective fresh reconstruction proves their accepted artifact/lineage semantics false or inapplicable. A bridge checkpoint orchestration defect is H1-10-owned. H1-04 reopens only if the accepted source/catalogue identity cannot be reproduced as claimed.
