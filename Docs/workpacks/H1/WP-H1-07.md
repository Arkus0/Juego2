# WP-H1-07 — Allowlisted component projection

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: LOCAL_UNITY_REQUIRED
Depends on: `WP-H1-06` PASS
Blocks: `WP-H1-08`

## Objective and central claim

Implement an explicit schema-adapter boundary for inspecting and realizing the finite component set required by the H1 slice, including structured canonical/catalogue references, without exposing generic arbitrary reflection mutation.

## WHY_THIS_BOUNDARY

Component field/reference semantics have their own finite adapter universe and can be wrong while prefab identity remains correct. One WP owns the complete initial adapter set; a WP per component would be administrative fragmentation.

## Inherited guarantees

H1-01 structured producer/dependency derivation, H1-04 catalogue/component-schema identity, H1-05/06 generation and asset relationships, H0 validation/mutation authority.

## H1-07 compression amendment

Binding planning amendment: `Docs/workpacks/H1/H1_07_COMPRESSION_AMENDMENT.md`.

H1-07 owns only the bounded component-adapter semantics introduced by this workpack: exact schema↔effective-adapter completeness, supported field/reference round-trip through the existing Unity materialize/save-reload/inspect path, exact canonical/catalogue target resolution, deterministic normalized component observation, fail-closed unsupported semantics, and binding the new capability into the existing canonical discovery/transports without a parallel registry.

H1-04 catalogue/source identity, H1-05 materialization/publication, H1-06 prefab/asset relationships, H0 authority/discovery/transport machinery and accepted source-slice/asset-distribution integrity are `CONSUMED / INTEGRATION_ONLY`. They must not be rebuilt or broadly re-proved inside H1-07.

A failed job is an H1-07 semantic blocker only when it directly falsifies an H1-07-owned component-adapter claim. A predecessor contradiction routes to that predecessor. Runner/workflow/logging/checkout, unrelated GitHub Pages/IngestPortal, unrelated asset-transport or other non-semantic execution failures are `EVIDENCE_OR_INFRA_BLOCKED`: they can prevent PASS until the bounded proof executes, but they do not justify speculative component-adapter repair or expansion of the H1-07 proof surface.

## New guarantees owned

- versioned component schema descriptors and adapter bindings;
- complete initial allowlist required by the representative slice;
- normalized read/write semantics for supported value/reference fields;
- exact derivation/resolution of canonical-object and catalogue references;
- unsupported component/field/type fails closed.

## Explicitly not re-proved

Generic Unity serialization, all third-party components, scene/prefab generation, canonical dependency semantics generally or final validation aggregation.

## Allowed scope

Transform refinement plus minimal Renderer/material, Animator/controller/clip and bridge-marker or test-owned component adapters required by H1-11; component query/get and realization evidence.

## Forbidden scope

Generic `SerializedProperty`/reflection endpoint over arbitrary types, runtime script execution, gameplay components, physics/navmesh behavior, arbitrary custom editors or hiding unsupported fields.

## Architecture / authority boundary

An adapter owns one stable namespaced component schema and maps portable fields to Unity. The effective adapter inventory must equal the declared supported schema inventory; neither list proves itself alone.

## Acceptance criteria

- every declared component schema has exactly one effective adapter and every effective adapter has one composed schema;
- supported scalar/vector/enum/reference fields round-trip through materialize -> save/reload -> inspect;
- structured references resolve to the same canonical/logical targets represented by the producer dependencies;
- unsupported component/type/field/reference yields stable failure before active generation publication;
- normalized component observation is deterministic and excludes volatile implementation fields;
- new component capabilities project through canonical discovery and both transports without parallel registries.

## Deterministic proof / evidence

Independently enumerate adapter implementations/effective realized components and compare with composed schemas. Exercise one object with multiple components, catalogue references and a canonical-object reference across reload/rebuild.

Per the binding compression amendment, this is a bounded proof obligation. Whole-project regressions, web-publication regressions, broad asset scanning and unrelated subsystem checks are not additional H1-07 semantic proof requirements.

## Causal negative-conformance classes

- adapter or schema omitted so both proof lists shrink;
- supported field silently ignored;
- canonical/catalogue reference resolved to wrong target;
- unsupported field accepted through reflection fallback;
- volatile field contaminates parity digest;
- transport schema drifts from composed component schema.

## Content-shape probe

Required. Exercise facade material assignment and humanoid Animator/clip references plus a canonical relationship; this is schema pressure, not animation gameplay proof.

## Dependency / IP implications

No new external package is expected. Each later third-party component package requires its own adapter/adoption decision.

## Residual risks

Only the initial allowlist is supported. Runtime component behavior, animation correctness and visual quality are later claims.

## Exact predecessor reopen condition

Reopen H1-01 if the accepted producer schema cannot encode a required supported field/reference without a breaking change. An omitted Unity adapter is owned here.

The compression amendment additionally requires causal routing: if effective evidence instead falsifies an accepted H1-04/H1-05/H1-06/H0 guarantee, reopen that causal predecessor under its existing rule rather than duplicating the mechanism in H1-07.

## PASS consequence / next dependency

PASS unblocks `WP-H1-08`.
