# WP-H1-07 — Allowlisted component projection

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: LOCAL_UNITY_REQUIRED
Depends on: `WP-H1-06` PASS
Blocks: `WP-H1-08`

## Objective and central claim

Implement an explicit schema-adapter boundary for inspecting and realizing the finite component set required by the H1 slice, including structured canonical/catalogue references, without exposing generic arbitrary reflection mutation.

## WHY_THIS_BOUNDARY

Component field/reference semantics have their own finite adapter universe and can be wrong while prefab identity remains correct. One WP owns the complete initial adapter set; a WP per component would be administrative fragmentation.

## Inherited guarantees

H1-01 structured producer/dependency derivation, H1-04 catalogue/component-schema identity, H1-05/06 generation and asset relationships, H0 validation/mutation authority, and the accepted ART-01 upstream/derived content baseline.

## New guarantees owned

- versioned component schema descriptors and adapter bindings;
- complete initial allowlist required by the representative slice;
- normalized read/write semantics for supported value/reference fields;
- exact derivation/resolution of canonical-object and catalogue references;
- unsupported component/field/type fails closed.

## Explicitly not re-proved

Generic Unity serialization, all third-party components, scene/prefab generation, ART source/derivative creation, canonical dependency semantics generally or final validation aggregation.

## Allowed scope

Transform refinement plus minimal Renderer/material, Animator/controller/clip and bridge-marker or test-owned component adapters required by H1-11; component query/get and realization evidence over accepted ART-01 upstream/derived assets.

## Forbidden scope

Generic `SerializedProperty`/reflection endpoint over arbitrary types, runtime script execution, gameplay components, physics/navmesh behavior, arbitrary custom editors, hiding unsupported fields, or creating/modifying character meshes, clothes or animation content to make the adapter proof pass.

## Architecture / authority boundary

An adapter owns one stable namespaced component schema and maps portable fields to Unity. The effective adapter inventory must equal the declared supported schema inventory; neither list proves itself alone. Character/outfit/animation content is an ART-owned catalogue input; H1-07 only projects and inspects its supported component references.

## Acceptance criteria

- every declared component schema has exactly one effective adapter and every effective adapter has one composed schema;
- supported scalar/vector/enum/reference fields round-trip through materialize -> save/reload -> inspect;
- structured references resolve to the same canonical/logical targets represented by the producer dependencies;
- unsupported component/type/field/reference yields stable failure before active generation publication;
- normalized component observation is deterministic and excludes volatile implementation fields;
- new component capabilities project through canonical discovery and both transports without parallel registries;
- the humanoid/Animator proof uses an accepted **clothed Juego2 civilian derivative** and accepted civilian animation inputs from ART-01 rather than a naked base-body production stand-in.

## Deterministic proof / evidence

Independently enumerate adapter implementations/effective realized components and compare with composed schemas. Exercise one object with multiple components, catalogue references and a canonical-object reference across reload/rebuild. The humanoid object uses an accepted ART-01 clothed civilian derivative plus accepted/retargeted civilian animation clip references.

## Causal negative-conformance classes

- adapter or schema omitted so both proof lists shrink;
- supported field silently ignored;
- canonical/catalogue reference resolved to wrong target;
- unsupported field accepted through reflection fallback;
- volatile field contaminates parity digest;
- transport schema drifts from composed component schema;
- missing ART character/outfit/clip input is hidden by substituting a different or naked placeholder while component proof reports success.

## Content-shape probe

Required. Exercise facade material assignment and a **clothed** humanoid Animator/clip reference plus a canonical relationship; this is schema pressure, not animation gameplay proof. Character/outfit/clip creation or editing belongs to ART, not H1-07.

## Dependency / IP implications

No new external package is expected. Content comes from the accepted ART-01 Quaternius Source/Juego2 Derived baseline. Each later third-party component package requires its own adapter/adoption decision.

## Residual risks

Only the initial allowlist is supported. Runtime component behavior, animation correctness, wardrobe breadth, NPC variety and visual quality are later claims.

## Exact predecessor reopen condition

Reopen H1-01 if the accepted producer schema cannot encode a required supported field/reference without a breaking change. An omitted Unity adapter is owned here. Reopen ART only when effective Unity evidence shows the accepted derived content/export contract itself is false or unusable, not merely because an adapter is missing.

## PASS consequence / next dependency

PASS unblocks `WP-H1-08`.
