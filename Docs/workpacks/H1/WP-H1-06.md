# WP-H1-06 — Asset/prefab realization + managed derivatives

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: LOCAL_UNITY_REQUIRED
Depends on: `WP-H1-05` PASS
Blocks: `WP-H1-07`

## Objective and central claim

Resolve logical catalogue bindings into truthful Unity asset/prefab relationships, instantiate source prefabs without overwriting them, and create only explicitly bridge-managed prefab derivatives inside the accepted generation boundary.

## WHY_THIS_BOUNDARY

Scene graph publication is already accepted by H1-05; this WP adds a distinct asset/prefab authority and reference-fidelity claim. Component property semantics are kept out because their adapter universe and error cases differ. Asset and prefab handling stay together because Unity prefab identity is an asset relationship, not a separate authority.

## Inherited guarantees

H1-04 catalogue identity and accepted Quaternius Source baseline, H1-05 generation/publication, H1-01 logical asset dependencies and H0 canonical authority.

## New guarantees owned

- source assets/prefabs are read-only catalogue inputs to bridge materialization;
- prefab instance/source/nested relationship is retained in normalized observation;
- managed prefab derivative identity, lineage and generation receipt;
- missing/wrong-type/rebound logical asset diagnostics;
- asset changes cannot silently change the canonical selection.

## Explicitly not re-proved

Catalogue completeness, scene publication mechanics, H1-04 source adoption/license decision, arbitrary components, Unity YAML byte stability, art quality or final production-asset breadth.

## Allowed scope

PrefabUtility/AssetDatabase use inside managed roots, source-prefab inspection/instantiation, managed bridge variants/derivatives, mesh/material/clip reference wiring needed by fixtures and accepted Quaternius Source content.

The term **managed derivative** here means a bridge-generated projection artifact needed to prove prefab/asset semantics. It is not the art-production pipeline for Cantabrian remodeling, clothing, missing props or bespoke animations.

## Forbidden scope

Overwriting the purchased Quaternius upstream/source baseline, arbitrary asset transformation factories, broad art-authoring/Cantabrian conversion, wardrobe production, Addressables/bundles, asset-store automation, gameplay or treating prefab contents as canonical state.

## Architecture / authority boundary

The canonical binding selects a logical catalogue ID. The catalogue resolves it; the bridge realizes it. Source asset bytes/native IDs remain external inputs recorded by catalogue fingerprint and receipt.

Quaternius Source remains the editable **upstream** for later art production, but H1 bridge proof treats the adopted upstream identity as stable input. Future Juego2 art derivatives are separate authored assets with their own provenance/catalogue identities; they are not bridge-managed derivatives merely because they originated from Quaternius.

## Acceptance criteria

- source prefab and nested relationships are inspectable and preserved after save/reload;
- purchased/adopted source files remain byte/semantic unchanged by bridge materialization;
- managed bridge derivatives exist only under managed roots with explicit source lineage;
- missing/incompatible/rebound logical IDs block truthful publication with stable diagnostics;
- replacing a catalogue mapping changes catalogue/plan evidence but not canonical world hash;
- repeated materialization is semantically idempotent;
- deleting generated bridge derivatives and rebuilding reproduces the normalized relationships.

## Deterministic proof / evidence

Use accepted Quaternius Source prefab/material relationships for the positive game-shaped proof, plus a distinct bridge-managed variant and harness-only malformed fixtures where necessary for causal controls. Observe effective prefab links before/after reload, protect source hashes and compare generation observations.

## Causal negative-conformance classes

- source prefab overwritten;
- prefab instance flattened while parity still reports success;
- nested/source lineage omitted;
- wrong asset type accepted;
- missing logical asset silently replaced by a default;
- generated bridge derivative outside managed root;
- source mutation changes canonical hash or is journaled as canonical authoring.

## Content-shape probe

Required. Use wall/roof/door/window/prop relationships from the accepted Quaternius Source baseline shaped like the approved street-corner slice; a lone primitive is insufficient. Harness-only synthetic assets may appear only where a deliberate defect/control requires them.

## Dependency / IP implications

Consumes the exact H1-04-approved Quaternius Source baseline; no new art source is adopted here. Upstream/source provenance and redistribution constraints remain visible. Later art production may create Juego2-derived versions when the demo actually needs Cantabrian adaptation or missing content, but that production ownership is outside this bridge WP.

## Residual risks

Complex model-importer adaptation, broad art transformation, clothing/wardrobe, vehicles, missing production props/meshes/animations and shipping asset delivery remain outside scope.

## Exact predecessor reopen condition

Reopen H1-04 only if effective Unity identity proves its catalogue mapping/source identity false or inapplicable. Prefab realization defects remain H1-06.

## PASS consequence / next dependency

PASS unblocks `WP-H1-07`.
