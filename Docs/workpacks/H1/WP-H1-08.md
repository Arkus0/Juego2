# WP-H1-08 — Unity validation + repairable diagnostics

Status: PLANNED / NOT_STARTED

EXECUTION_REQUIREMENT: HYBRID
Depends on: `WP-H1-07` PASS
Blocks: `WP-H1-09`; provides the bridge prerequisite for `WP-CITY-04`

## Objective and central claim

Provide stable machine-actionable Unity-owned diagnostics for binding, catalogue, scene, prefab, managed marker and component invariants at both preflight and effective post-materialization boundaries, without duplicating or suppressing H0 diagnostics.

## WHY_THIS_BOUNDARY

Validation is a distinct authority: a materializer can write what it was told and still fail to detect an invalid Unity result. Combining diagnostics with reconciliation would let repair direction hide incomplete detection. All Unity invariants stay together because they share one aggregation/actionability claim.

## Inherited guarantees

HK05 canonical diagnostic semantics, H1-01 producer validation, H1-04 catalogue, H1-05/06/07 effective projection, H1-03 authority and H1-03A public Editor execution/lifecycle.

## Remaining-work compression amendment

Binding planning amendment: `Docs/workpacks/H1/H1_REMAINING_COMPRESSION_AMENDMENT.md`.

H1-08 must consume HK05 diagnostic semantics and the causal checks already owned by H1-04/05/06/07. Its new implementation ownership is validator/invariant composition, Unity-specific deterministic aggregation, truthful preflight/postflight separation, publication blocking after failed postflight, and genuinely unowned Unity invariants. It must not build a parallel generic diagnostics framework or reimplement predecessor validity checks only to aggregate them.

## New guarantees owned

- finite independently checked Unity invariant/validator inventory;
- stable diagnostic code/severity/canonical resource/logical asset/managed path/context;
- deterministic aggregation with dependency-local ambiguity;
- preflight and post-materialization validation, with truthfully distinct phases;
- invalid projection cannot receive a successful active-generation receipt.

## Explicitly not re-proved

HK05 invariants, H1 materialization implementation, drift repair authority, visual quality, gameplay or every Unity warning.

## Allowed scope

Unity validators, diagnostic schemas/aggregation, public validate capabilities, focused remote schema and local effective tests.

## Forbidden scope

Natural-language repair generation, global suppression after one ambiguity, importing fixes automatically, gameplay/nav/physics/visual-quality validators or converting Unity exceptions into the normal expected contract.

## Architecture / authority boundary

Canonical diagnostics remain HK05-owned. Unity diagnostics may reference the same canonical resource but use distinct namespaced invariant IDs. Ambiguity in one mapping/asset suppresses only dependent secondary diagnostics.

## Acceptance criteria

- every owned Unity invariant is independently enumerable, registered once and effectively exercised;
- missing asset/type, duplicate marker, broken prefab link, invalid component field/reference, non-finite transform and plan/observation mismatch are represented;
- independent violations aggregate deterministically and actionably;
- preflight rejects known-invalid plans before staging; postflight rejects unexpected effective results before publication;
- public current/proposed validation is discoverable/versioned;
- expected invalidity yields structured results, not raw Unity exceptions;
- complete H0 diagnostics remain obtainable and are not relabeled as Unity findings.

## Deterministic proof / evidence

Use independent invariant IDs plus effective invalid fixtures. Reverse ambiguous inputs, include a disjoint validly identified defect, and compare complete diagnostics. Validate the representative scene before and after materialization.

## Causal negative-conformance classes

- missing validator registration;
- validator registered but never effectively runs;
- one invalid projection route skips validation;
- ambiguous identity changes diagnostic set/order;
- global ambiguity suppression hides independent issue;
- emitted location identifies only a volatile Unity locator;
- Unity exception escapes as expected public failure.

## Content-shape probe

Required. Introduce one bad prefab/material/component reference and one independent hierarchy defect in the approved street-corner shape; classify findings without extending gameplay scope.

## Dependency / IP implications

Consumes accepted Unity packages only. No external validation framework becomes invariant authority.

## Residual risks

Console warnings outside the owned inventory, aesthetic defects, runtime behavior and unknown third-party custom serialization remain outside scope.

## Exact predecessor reopen condition

Reopen HK05 only if effective H1 evidence shows the accepted canonical diagnostic contract cannot carry required generic repair context. Unity-specific invariant omissions are H1-08-owned.
