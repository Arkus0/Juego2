# WP-H1-03 — Unity host policy + project workspace authority

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL AUTHORITY
EXECUTION_REQUIREMENT: HYBRID
Depends on: `WP-H1-01` PASS, `WP-H1-02` PASS
Blocks: `WP-H1-04`

## Objective and central claim

Introduce a versioned H1 Unity host policy that admits only reviewed project-local editor effects and enforces that policy below transports, without weakening or relabeling the accepted H0 host policy.

## WHY_THIS_BOUNDARY

Host authority is a causal seam independent of catalogue or materialization correctness; HK09A proved why testing only a preferred entrypoint is insufficient. Keeping policy separate lets review reject an authority path without conflating it with Unity feature behavior.

## Inherited guarantees

HK00A scoped-provider ownership, HK07 neutral projection, HK09A H0 admission/absence of generic powers, HK09B resource semantics, H1-00 bridge side-effect classes, H1-01 provider and H1-02 fixed project root.

## New guarantees owned

- separate `arkus.unity-host-policy@1` admission boundary;
- fixed bootstrapped project identity and managed asset roots;
- truthful read-only versus `ExternalReversible` bridge metadata;
- no arbitrary caller path, shell/process, network endpoint or runtime-type activation;
- every JSONL/MCP/future adapter crosses the same policy before Unity exposure/dispatch.

## Explicitly not re-proved

All HK09A H0 paths, asset catalogue completeness, materialization transactionality or Unity sandboxing against a hostile OS/account.

## Allowed scope

H1 composition/host factory, policy metadata/validation, project/workspace capability tokens, transport-delta tests and local Unity admission fixtures.

## Forbidden scope

Weakening `H0HostCapabilityPolicy`, generic filesystem/process/network tools, user-selected roots, package installation through public authoring, cloud/auth, scene/prefab feature implementation or gameplay.

## Architecture / authority boundary

Bootstrap supplies the project root/identity out of band. Public requests select logical resources inside reviewed managed roots, never raw host paths. H0 and H1 host profiles remain distinguishable and versioned.

## Acceptance criteria

- H0 composition behavior is unchanged;
- Unity provider capabilities are rejected by the H0 profile and admitted only by the H1 profile when metadata is complete;
- direct generic composition cannot be projected into Unity without H1 policy admission;
- path-shaped, URL-shaped, process-shaped and runtime-type-shaped payloads cannot acquire corresponding ambient authority;
- reference/MCP expose no adapter-only Unity power;
- ordinary H0 read/mutation operations plus admitted Unity reads/effects remain usable;
- resource/time policy for Unity operations is explicit or conservatively bounded for later refinement.

## Deterministic proof / evidence

Remote contract/policy tests plus local Unity proof that effective editor calls stay inside the bootstrapped project/managed roots. The causal seam starts from a valid generic composed provider, not the preferred host factory.

## Causal negative-conformance classes

- generic composition reaches Unity without admission;
- raw path escapes the managed root;
- adapter mints a Unity-only power absent from composition;
- Unity capability lies about side effect/privilege;
- H0 profile accidentally admits Unity effects;
- public payload triggers package install, process or network authority.

## Content-shape probe

Required because public host capability semantics change. Use the bounded market slice to show normal authoring plus Unity read/effect admission requires no forbidden ambient power.

## Dependency / IP implications

Consumes only packages accepted by H1-02. New packages or hosted services are forbidden without separate reviewed adoption.

## Residual risks

This is application-level project containment, not OS sandboxing, authentication or hostile plugin isolation.

## Exact predecessor reopen condition

HK09A reopens only if H1 changes an accepted H0 effective path. Legitimate new Unity authority belongs here and does not by itself falsify HK09A.

## PASS consequence / next dependency

PASS unblocks `WP-H1-04` and closes the authority prerequisite for all later Unity effects.
