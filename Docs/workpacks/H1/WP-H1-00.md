# WP-H1-00 — Engine-neutral projection contract + reference materializer

Status: PLANNED / NOT_STARTED

EXECUTION_REQUIREMENT: REMOTE_OK

## Objective and central claim

Implement the engine-neutral, versioned projection state machine defined by the H1 architecture and exercise it with a deterministic non-Unity reference materializer. The claim is that canonical input, projection plan, staged generation, normalized observation, receipt and drift states have truthful semantics without engine types or canonical write authority.

## WHY_THIS_BOUNDARY

This WP owns one neutral contract and an implementation that makes it executable. A contract without a consumer would be speculative; a Unity implementation in the same WP would couple the neutrality claim to editor/toolchain failures. The reference materializer gives independent value and a falsifiable contract while `WP-H1-05` later proves Unity fits it unchanged.

## Inherited guarantees

Consumes HK02 identity/hash, HK04/HK05 mutation/validation authority, HK06 evidence semantics, HK07 neutral projection and HK09A/HK09B H0 boundaries.

## New guarantees owned

- versioned bridge input/plan/observation/receipt/drift contracts;
- full input tuple includes canonical anchor, binding version, catalogue fingerprint and bridge/toolchain profile;
- materialization never mutates canonical state;
- staged generation publishes only after validation/observation success;
- deterministic normalized plan/observation and idempotent retry in the reference materializer.

## Explicitly not re-proved

Canonical mutation atomicity, H0 validation completeness, journal/snapshot/replay, MCP/JSONL full parity, host containment or H0 resource closure.

## Allowed scope

Engine-neutral assemblies, portable schemas, reference in-memory/fileless materializer, focused tests, evidence and architecture reconciliation.

## Forbidden scope

Unity assemblies/types, AssetDatabase, real project files, asset catalogue implementation, gameplay, new canonical mutation route or H0 contract reinterpretation.

## Architecture / authority boundary

Projection is downstream of an immutable canonical snapshot. Receipts are bridge evidence, not HK06 mutation entries. The reference materializer may simulate generations only; it cannot become a second world store.

## Acceptance criteria

- all contract artifacts are versioned, portable and deterministic;
- same full input yields equal plan/digest/observation and no semantic second-apply delta;
- changed canonical anchor, binding schema or catalogue fingerprint changes the relevant identity/digest;
- failure before publication leaves the prior generation active;
- observation can distinguish absent, in-sync, canonical-ahead, engine-drift, missing-dependency, ambiguous and failed states;
- the canonical snapshot is byte/hash unchanged before and after every bridge action;
- no engine/runtime implementation type appears in protocol/kernel dependencies.

## Deterministic proof / evidence

An executable reference scenario models a small hierarchy with two logical asset dependencies, stages/publishes it, repeats idempotently, injects interruption, introduces drift and rebuilds from the same inputs. Evidence compares effective normalized plans/observations, not a self-declared registry.

## Causal negative-conformance classes

- receipt omits or misanchors canonical/catalogue input;
- same input produces a different normalized plan;
- failed staging changes the active generation;
- bridge path mutates canonical bytes/hash;
- drift observation hides an extra/missing/changed managed resource;
- engine-specific type leaks into the neutral project graph.
