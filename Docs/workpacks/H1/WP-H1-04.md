# WP-H1-04 — Unity catalogue + identity resolution

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: LOCAL_UNITY_REQUIRED
Depends on: `WP-H1-03A` PASS + `WP-ART-01` PASS
Blocks: `WP-H1-05`

## Objective and central claim

Expose a deterministic, complete-for-declared-scope Unity catalogue of scenes, upstream source assets, Juego2 Derived assets, prefabs, materials, clips and component schemas, with stable Arkus logical IDs mapped to effective Unity locators without making the catalogue canonical `WorldState`.

H1-04 is the first H1 point that consumes game-representative art. The actual source selection/adaptation pipeline is owned by `WP-ART-01`; H1-04 owns only truthful Unity import/catalogue identity over the accepted upstream + derived baseline.

## WHY_THIS_BOUNDARY

Inventory/identity is read-only and has a different completeness oracle from materialization. It can be correct while writes are unsafe, or false while a hand-picked scene appears to materialize. Asset classes stay together because they share one catalogue authority and snapshot/fingerprint contract.

Art-source selection, clothing/mesh/animation authoring and derivative provenance are intentionally outside this WP because those are product-content claims owned by ART. H1-04 must not become an art-production workpack merely because it is the first bridge stage that needs real content.

## Inherited guarantees

HK01/HK03 discoverability and bounded reads, HK07 projections, HK08 pagination/cost semantics, H1-01 catalogue-reference vocabulary, H1-02 project identity, H1-03 authority and H1-03A public Editor execution/lifecycle, plus the accepted `WP-ART-01` Quaternius Source → Juego2 Derived provenance/adaptation baseline.

## New guarantees owned

- versioned catalogue entry/snapshot/fingerprint contracts;
- stable logical IDs separate from path/GUID/file-ID/`GlobalObjectId`;
- bounded query/get for admitted upstream source assets, Juego2 Derived assets, prefabs, scenes, materials, clips and component schemas;
- explicit catalogue metadata distinguishing upstream Quaternius source items from Juego2 Derived items while preserving their stable logical identities and provenance references;
- deterministic collision/missing/incompatible diagnostics;
- independently/effectively bounded completeness universe for reviewed roots/types.

## Explicitly not re-proved

Canonical object identity, generic H0 query correctness, ART-01 source/license/style/derivative correctness, materialization, source-asset mutability, arbitrary Unity-project completeness, full-pack Quaternius coverage, final art quality or H1-11's broad real-asset conformance claim.

## Allowed scope

AssetDatabase/editor inspection, import observation, mapping manifest, catalogue scoped capabilities, pagination, snapshot fingerprint and focused local evidence over the accepted ART-01 source/derived slice.

Repository-owned synthetic content remains allowed only for harness-only proof objects that are not substitutes for game art (for example bridge markers or deliberately malformed negative-test fixtures).

## Forbidden scope

Serializing the asset database into `WorldState`, using paths/native IDs as canonical identity, writing upstream source assets, authoring clothing/meshes/animations, scanning outside approved project roots, runtime asset delivery/addressables, gameplay, keeper/CITY production, or creating substitute production-intent art inside H1 when ART-01 provides an accepted upstream/derived content shape.

## Architecture / authority boundary

Catalogue state is project integration state. Canonical bindings reference logical IDs; effective locators remain bridge evidence. The accepted universe is all matching effective assets under explicit reviewed roots, not whatever rows happen to be registered in the mapping manifest.

Quaternius Source items and Juego2 Derived items are read-only catalogue inputs to the bridge. ART owns their source/derivative lineage; H1 owns the logical/native mapping and truthful effective observation. Neither source files nor derived art define Arkus canonical identity or schemas.

## Acceptance criteria

- the exact ART-01 handoff identifies the admitted upstream Quaternius Source and Juego2 Derived items used by the candidate;
- public bounded discovery describes each admitted unit with stable logical identity, type, relevant dimensions/dependencies, adoption/provenance class and effective locator;
- moving an asset while preserving Unity identity preserves logical identity;
- copying creates distinct native identity and cannot alias the source logical ID;
- missing/duplicate/stale mappings fail visibly;
- upstream and derived items cannot silently alias one logical identity;
- unchanged effective inventory produces an identical normalized catalogue snapshot/fingerprint;
- catalogue changes do not change canonical world hash;
- a referenced missing/incompatible entry is detectable before truthful materialization;
- capability inventory comes from canonical composition, not a Unity-only registry;
- production-intent content in the H1-04 content-shape probe uses accepted ART-01 upstream/derived assets rather than locally fabricated replacement art.

## Deterministic proof / evidence

Build a small effective Unity inventory containing accepted ART-01 Quaternius Source and Juego2 Derived items: facade/module or prop shape, material/atlas, clothed civilian derivative and civilian animation clip, plus only harness-specific repository-owned proof objects where needed. Compare AssetDatabase/type enumeration against the normalized catalogue and mapping, then exercise move/copy/delete/reimport cases in a disposable project copy. Preserve the ART provenance IDs and exact effective catalogue fingerprint used by the candidate.

## Causal negative-conformance classes

- manifest row removed so asset and obligation disappear together;
- move changes logical identity;
- copy aliases source;
- upstream and derived asset identities collapse together;
- path or `GlobalObjectId` presented as canonical identity;
- stale/missing asset remains silently usable;
- catalogue mutation changes canonical state/hash;
- one public catalogue entry disappears from JSONL or MCP;
- accepted ART provenance/adoption identity is missing while the catalogue presents the asset as approved;
- substitute game-art fixture is silently used in place of the accepted ART-01 content.

## Content-shape probe

Required. Use accepted ART-01 game-representative upstream/derived content for the facade/module, material, clothed civilian and civilian animation-clip shapes. Repository-owned synthetic fixtures are acceptable only for harness-specific mechanics or causal negative controls; they must not stand in for production-intent art.

## Dependency / IP implications

`WP-ART-01` owns exact Quaternius source adoption, derivative provenance and source-distribution boundaries. H1-04 verifies that only accepted items enter the reviewed catalogue and that provenance/adoption status survives import/discovery. If an unadmitted source or derivative is needed, route back to ART rather than silently expanding H1 scope.

H1-05 through H1-10 consume this same accepted ART-01 baseline when they need game-representative assets. They may add harness-only test fixtures, but must not introduce alternative substitute production art by default.

## Residual risks

The catalogue is complete only for declared roots/types. Full Quaternius pack coverage, broad wardrobe/NPC variety, broad animation coverage, production asset breadth, Addressables delivery, external repositories and cross-project identity remain outside scope; ART/H2 expand content while H1-11 owns representative bridge conformance breadth.

## Exact predecessor reopen condition

Reopen H1-01 only if its logical reference cannot represent an admitted catalogue entry without changing public semantics. Reopen ART-01 only if effective import proves the accepted source/derived provenance or export contract false/inapplicable. Native Unity lifecycle difficulty belongs here, not in ART/H0.

## PASS consequence / next dependency

PASS unblocks `WP-H1-05` and establishes the logical/effective Unity catalogue over the accepted Quaternius Source + Juego2 Derived baseline.
