# WP-H1-02 — Reproducible Unity project + toolchain baseline

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL TOOLCHAIN
EXECUTION_REQUIREMENT: LOCAL_UNITY_REQUIRED
Depends on: `WP-HK-GATE` PASS
Blocks: `WP-H1-03`

## Objective and central claim

Create the minimal Unity project substrate on an exact Unity 6.3 LTS patch with pinned packages, Force Text serialization and reproducible batchmode tests, while keeping H0 kernel assemblies engine-neutral and editor binaries out of the repository.

## WHY_THIS_BOUNDARY

Toolchain reproducibility, package/IP adoption and project layering can pass or fail before any bridge authority exists. Mixing them with host policy or materialization would make editor/package failures obscure semantic review. Splitting each package is administrative fragmentation, so the whole baseline remains one WP.

## Inherited guarantees

HK00 reproducible build discipline, HK00A dependency/IP and anti-lock-in rules, H0 engine-neutral project graph and HK-GATE authorization to begin Unity work.

## New guarantees owned

- exact Unity editor version and install fingerprint;
- locked minimal package graph and exact license/adoption records;
- reproducible project open/compile/EditMode test in batchmode;
- Force Text and visible `.meta` identity policy;
- assembly-definition direction preventing Unity dependencies from entering H0 assemblies;
- chosen render-pipeline baseline for the retained project.

## Explicitly not re-proved

H0 .NET build closure, canonical semantics, bridge contracts, asset identity or materialization.

## Allowed scope

Unity project settings, `ProjectVersion.txt`, package manifest/lock, assembly definitions, minimal bootstrap/test code, canonical local invocation script and dependency records.

## Forbidden scope

Bridge public capabilities, scene production, imported third-party art, gameplay, materialization logic, arbitrary package growth or committed Unity editor/cache binaries.

## Architecture / authority boundary

The Unity project may reference compatible Arkus `netstandard2.1` assemblies through reviewed adapter assemblies. No `UnityEngine`/`UnityEditor` reference may flow back into canonical projects.

## Acceptance criteria

- an exact 6.3 LTS patch is selected from official releases and recorded;
- a clean local checkout opens and runs the canonical batchmode EditMode suite without prompts;
- package versions/resolution are locked and the render pipeline/test framework are explicitly justified;
- Force Text, visible meta files and deterministic project settings are committed;
- editor-generated caches/build outputs remain ignored;
- project/assembly graph proves H0 projects have no Unity dependency;
- a second clean project import produces the same effective package/assembly inventory.

## Deterministic proof / evidence

Record exact editor/package/platform fingerprints, clean-import commands and two effective batchmode inventories. A small editor-open smoke may be used, but the oracle is effective compilation/test/package state.

## Causal negative-conformance classes

- package lock or exact editor pin removed;
- Unity reference introduced into a canonical assembly;
- an untracked/hidden package becomes required;
- Force Text/meta identity disabled;
- batchmode requires a prompt or interactive state;
- proof reads only the declared manifest while effective resolved packages differ.

## Content-shape probe

Not applicable: no authorable/public state semantics are introduced.

## Dependency / IP implications

This WP owns exact Unity editor/package adoption records and terms. Unity 6.3 LTS is the planned family; the Worker selects the exact maintained patch. No asset pack is adopted here.

## Residual risks

Editor availability/licensing remains a local prerequisite; byte-identical imports across OSes and future Unity upgrades are not claimed.

## Exact predecessor reopen condition

Reopen HK00/HK00A only if the actual Unity integration requires changing their engine-neutral product/build boundary, not merely adding an adapter project.

## PASS consequence / next dependency

Together with `WP-H1-01` PASS, this unblocks `WP-H1-03`.
