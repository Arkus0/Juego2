# WP-H1-01 — Unity scoped authoring producer + dependency derivation

Status: PLANNED / NOT_STARTED
Class: FOUNDATIONAL
EXECUTION_REQUIREMENT: REMOTE_OK
Depends on: `WP-H1-00` PASS
Blocks: `WP-H1-03`

## Objective and central claim

Add a Unity-scoped provider through the accepted canonical composer whose structured binding producer normalizes/encodes Unity authoring intent and mechanically derives every canonical-object and catalogue reference it understands.

## WHY_THIS_BOUNDARY

This is the public authored-contract/dependency claim, not editor execution. It can be implemented, reviewed and rejected entirely against portable data and H0 composition. Combining it with Unity materialization would make schema/authority failures indistinguishable from editor failures; splitting its individual binding fields would create micro-WPs and provisional schemas.

## Inherited guarantees

HK00A/HK01 scoped composition and versioning, HK02A opaque extensions/typed canonical dependencies, HK04 mutation authority, HK07 generic projection, HK08 interaction primitives and H1-00 bridge artifact semantics.

## New guarantees owned

- one versioned Unity binding document for the initial admitted vocabulary;
- schema-aware compile/decode/inspect capabilities accepted into the composed canonical inventory;
- canonical-object dependencies derived into HK02A metadata;
- catalogue dependencies derived into provider-owned typed binding/plan data;
- no caller-maintained duplicate dependency truth and no Unity-owned public registry.

## Explicitly not re-proved

HK01 route completeness generally, HK02A generic opaque payload semantics, HK04 commits, full transport parity, Unity asset existence or materialization.

## Allowed scope

Portable Unity-scoped schemas, codec/normalizer, dependency derivation, composed provider/bindings, delta JSONL/MCP conformance, focused evidence.

## Forbidden scope

UnityEngine/UnityEditor references, direct asset paths/GUID authority, canonical kernel introspection of arbitrary payload bytes, canonical commit outside H0, scene/prefab writing or gameplay schemas.

## Architecture / authority boundary

The provider compiles structured intent into an ordinary canonical extension mutation fragment. The client still uses H0 `plan/dry-run/apply`. Raw opaque authoring remains a low-level primitive and gains no false automatic-reference claim.

## Acceptance criteria

- provider identity/namespace/schema/version and bindings pass canonical composition;
- bindings cover target scene, normalized local transform, logical asset/prefab ID, allowlisted component documents and structured references without Unity CLR types;
- each structured canonical reference has exactly the derived HK02A dependency;
- each structured catalogue reference appears exactly once in derived catalogue dependencies;
- inconsistent caller-provided dependency metadata fails closed;
- schema evolution follows HK01 compatibility/version rules;
- new scoped capabilities appear through JSONL and MCP from composition without adapter edits;
- decode/inspect reconstructs the normalized authored binding needed for safe modification.

## Deterministic proof / evidence

Use a bounded Potes facade object referencing a market root, prefab, material and animation clip. Compare independently walked structured references against emitted dependencies and round-trip the normalized document. Run only delta transport conformance for the new provider.

## Causal negative-conformance classes

- one embedded canonical reference omitted from HK02A dependencies;
- one catalogue reference omitted or mis-typed;
- duplicate/contradictory caller dependency accepted;
- provider public route absent from one transport despite accepted composition;
- semantic schema change under the same version;
- Unity runtime/editor type appears in the portable contract graph.

## Content-shape probe

Required because this WP defines authorable/public semantics. The probe is an omission detector for hierarchy/reference/material/animation shapes, not evidence that those Unity resources exist yet.

## Dependency / IP implications

No Unity package dependency is allowed in this WP. Portable contract code must remain usable without an editor installation.

## Residual risks

Asset existence/type compatibility and component effective serialization remain later Unity-owned proofs. Generic external-resource references outside this provider remain unmodeled.

## Exact predecessor reopen condition

HK02A reopens only if effective structured producer evidence shows its accepted dependency surface cannot truthfully express a canonical-object reference. Catalogue references alone do not satisfy that condition because they are outside the canonical world-object universe.

## PASS consequence / next dependency

Together with `WP-H1-02` PASS, this unblocks `WP-H1-03`.
