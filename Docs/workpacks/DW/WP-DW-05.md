## Objective and central claim

Challenge the shared DW/Arkus boundary after both CITY and PA consumers exist, prove that their successful use did not rely on hidden domain-specific kernel assumptions, route every discovered generic limitation to its causal owner, and produce explicit evidence for what H2 should or should not freeze into the future public product boundary.

## WHY_THIS_BOUNDARY

CITY and PA can both pass while sharing the same accidental project-specific assumption. Conversely, every inconvenience could be misclassified as a kernel flaw and trigger needless H0 churn. A separate stress/assessment WP forces classification after real consumers exist and before the closure-only gate.

## Inherited guarantees

Consumes all DW-00..04 evidence plus accepted H0/H1 planning boundaries and the existing H2 future-planning signal. It does not supersede H1-GATE or pre-authorize H2.

## New guarantees owned

- explicit domain-leakage audit across shared DW/H0 public contracts and implementation dependencies;
- a tiny synthetic neutral third-shape probe using the already accepted generic DW envelope, sufficient only to detect CITY/PA hard-coding;
- classification of every discovered limitation as domain need, DW tooling need, generic Arkus contradiction/deficiency or downstream residual;
- zero silent H0 semantic changes inside the DW track;
- a versioned H2 boundary-input report distinguishing required consequences, optional opportunities and rejected/premature ideas;
- reconciliation of all DW residuals before the gate.

## Explicitly not re-proved

Full arbitrary-domain universality, external packaging/distribution, Unity bridge readiness, CITY/PA substantive truth, CTX process correctness or future H2 product behavior.

## Allowed scope

Domain-leakage/static dependency checks, the minimal neutral probe, residual/limitation classification, H2 planning-input documentation, focused tests/evidence and causal reopen proposals if required.

## Forbidden scope

Implementing an H0 fix inside this WP, adding a third production domain, external enterprise/medical/legal product work, Unity integration, gameplay, process-state modeling or turning H2 planning input into accepted H2 scope without H2 review.

## Architecture / authority boundary

The neutral probe consumes the same generic DW envelope/public Arkus seams but defines a schema unrelated to CITY/PA. It is a boundary falsification fixture, not a third product. If it exposes a generic contradiction, this WP records the exact failing public seam and stops short of repair; a separately reviewed causal owner must fix/reopen it.

- shared generic DW/H0 contracts and kernel dependencies contain no CITY/PA-specific vocabulary or behavior required for success;
- a minimal neutral typed graph can project, query, validate provenance and rebuild through the same generic DW envelope without modifying H0;
- the neutral probe has one causal invalid mutation that REDs through the same generic validation/provenance path;
- all limitations discovered by DW-00..04 are enumerated from evidence and assigned exactly one classification/owner;
- no accepted H0 file/contract/oracle was semantically changed by DW implementation without a separately accepted reopen/delta;
- the H2 input report states which public capabilities were actually exercised by CITY/PA, which limitations remain, and which downstream opportunities are deliberately not yet contracts;
- design↔Unity drift, generated art briefs, content-catalogue coverage, replay QA and narrative knowledge checks are preserved as downstream candidates with dependency/owner prerequisites rather than silently implemented;
- the report does not claim arbitrary-domain universality or external-repository consumability from in-repo evidence.
