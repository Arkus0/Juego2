# WP-H2F-03 — Integrated compatibility + AI-authoring benchmark

Status: **PROPOSED / NOT_STARTED**  
Class: `PRODUCT_CHECKPOINT`  
Mode: **LOCAL / real Unity visual-play evidence required**  
Depends on: `WP-H2F-02` PASS  
Blocks: `WP-H2F-GATE`

## Claim

The frozen candidate stack works as one coherent Juego2 production baseline when rendering, worldbuilding, traversal/navigation and character presentation are exercised together, and a fresh author/agent can use the prescribed Juego2-side surfaces without turning plugin-private state into canonical authority.

## Fixture rule

Use a bounded **`H2F_INTEGRATION_FIXTURE / NON_KEEPER`** fixture.

It may reuse admitted ART-01 assets, dimensions, composition rules and representative conditions, but it must be visibly recorded as a compatibility fixture. It cannot satisfy CITY-07 keeper acceptance, replace the retained CITY seed or become a backdoor redesign of CITY semantics.

The fixture should be as small as possible while exposing cross-tool failures: one short exterior route/street or path, meaningful level/edge treatment, one threshold/window/interior-depth condition, bounded nature, one player route and one representative humanoid.

## PASS-before-work acceptance contract

- **Positive claim:** the selected H2F stack coexists on one real Unity fixture and supports the complete minimal authoring/play path needed before CITY-07 commits keeper content.
- **Mandatory positive evidence:** (1) continuous third-person capture/inspection of the integrated fixture; (2) rendering/material evidence under the frozen URP baseline; (3) selected linear/terrain/nature/edge tooling exercised together; (4) player camera/input + collision/navigation exercised; (5) one actual Quaternius humanoid using the selected animation/retarget baseline plus any adopted rigging/IK correction; (6) one fresh-author/agent operation using the approved adapter/preset/public path; (7) bounded performance/profiler snapshot; (8) issue ledger distinguishing stack blocker from later art polish.
- **Negative gates:** FAIL if each package only works in its own demo scene; if the fixture hides incompatible materials or tools; if a plugin-private object graph becomes the only authoring API; if an AI directly mutates Unity/plugin state while presenting that as canonical Arkus authoring; if visual evidence is editor/top-down only; or if this fixture is promoted as CITY-07 keeper content.
- **Non-claims:** no final keeper level, no whole-town performance, no H3 routine/schedule semantics and no final ART-02 polish.
- **Allowed residuals:** visual tuning and content breadth that do not call the selected toolchain choice into question; later profiling-driven optimization; deferred categories already recorded by H2F-01.
- **Evaluation method:** human third-person visual/play inspection + bounded machine-verifiable configuration/navigation/identity checks + profiler evidence + fresh-author transcript.
- **Consumed predecessors:** H2F-02 exact adoption, ART-01 source/assembly truth and accepted H1 canonical→Unity/reconciliation authority.

## Required integrated capabilities

Exercise every capability selected as `ADOPT_NOW` that can interact materially with the representative CITY-07/H2 slice. The fixture must include, when selected/applicable:

- URP materials/shaders + baseline Volume/lighting/probe configuration;
- decals/SSAO or other selected renderer features;
- terrain/elevation and one linear spline/road/path realization;
- edge/kerb/retaining/wall treatment sufficient to expose overlap/seam problems;
- vegetation/scatter with road/building/threshold exclusions;
- water/shoreline if H2F-01 selected it as near-term retained technology;
- window/fake-interior or threshold/interior-depth treatment if selected;
- third-person controller/camera/input baseline;
- collision + selected navigation solution;
- one Quaternius character with selected Humanoid retarget/animation source;
- adopted Animation Rigging/IK contact correction if part of the baseline;
- one bounded interaction hook sufficient to prove compatibility with later H2-03 without implementing narrative systems;
- capture/profiling tooling required by the baseline.

Capabilities deliberately `DEFER`/`NO_ADOPT` do not need synthetic coverage.

## Fresh-author / Astra trial

A fresh capable author/agent receives only the accepted H2F/ART/H1 public documentation and fixture brief needed for the operation.

It must perform one bounded operation relevant to future keeper work, for example:

```text
inspect admitted realization profiles
-> discover legal route/path/edge/nature options
-> request one bounded semantic/local change through the accepted Arkus path where canonical world intent is involved
-> materialize/use the selected Unity-side profile
-> inspect the result
-> prove unrelated fixture content was not silently regenerated
```

When the operation is purely downstream visual tooling with no canonical semantic change, direct use of the documented Unity-side adapter/preset is allowed, but it must remain clearly classified as realization state rather than canonical world truth.

## Performance sanity

Record a bounded profiler snapshot on the integrated fixture:

- CPU/frame timing context;
- GPU/render timing where available and meaningful;
- draw-call/batch/triangle or equivalent scene-complexity indicators;
- memory snapshot or summary sufficient to catch an obviously pathological baseline;
- selected tool-specific warnings/errors.

This is not a shipping performance budget. Its purpose is to catch a foundation choice that is already obviously inappropriate before CITY-07 scales it.

Do not adopt optimization middleware merely to make this tiny fixture green unless the measured blocker is causal and H2F-01's decision is formally amended.

## PASS only if all are true

- all applicable `ADOPT_NOW` cross-cutting capabilities coexist on one fixture;
- representative Quaternius content renders correctly under the frozen URP baseline;
- selected road/path/terrain/nature tools do not produce unresolved overlap/seam/traversal blockers in the fixture;
- the player can traverse the fixture with the selected camera/input/collision/navigation baseline;
- one real Quaternius humanoid demonstrates the selected retarget/animation baseline at human scale;
- the fresh author/agent can perform one bounded operation through the prescribed boundary without hidden canonical authority;
- no unrelated accepted content is silently regenerated by that operation;
- profiler evidence shows no obvious foundation-level blocker for moving to the bounded keeper slice;
- all remaining issues are classified as H2F blocker, causal predecessor contradiction or permitted later residual;
- the fixture remains explicitly non-keeper.

## Negative gates

The acceptance-contract negative gates are binding. Package-by-package demo success without one composed Juego2 fixture is an explicit FAIL.
