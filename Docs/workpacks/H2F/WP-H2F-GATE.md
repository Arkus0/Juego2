# WP-H2F-GATE — H2 product/toolchain foundation freeze

Status: **PROPOSED / NOT_STARTED**  
Class: PRODUCT / TOOLCHAIN GATE  
Mode: **HYBRID** — documentary/adoption checks may be remote; effective Unity visual/play evidence is local or equivalent truthful hosted Unity evidence  
Depends on: `WP-H2F-00` PASS + `WP-H2F-01` PASS + `WP-H2F-02` PASS + `WP-H2F-03` PASS  
Blocks: ART-01 effective Unity `CANDIDATE`/PASS, `WP-CITY-07`, `WP-GC2-00`, `WP-H2-01`, `WP-H2-02` and any keeper production that relies on the selected H2F baseline

## Post-01A urban product amendment (prospective)

The gate freezes a reusable production foundation for compact urban blocks as well as the retained CITY-07 pilot. If 01A admitted Core, its public GC2↔Arkus adapter/lifecycle is part of the selected foundation. GC2-00 consumes this gate and proves the later gameplay round trip. Do not demand a keeper port district, 80–120 NPCs or separately licensed gameplay modules as foundation PASS. Arkus remains active canonical authority; all original reproducibility and H1 lifecycle obligations remain binding.

## Claim

Juego2 has a coherent, deliberately selected, exact-version and reproducible Unity/product baseline for the first keeper slice, and later ART/CITY/H2 Workers can build retained content without reopening foundational rendering/worldbuilding/player/navigation/character-animation tooling choices by accident.

This Gate does **not** claim the keeper slice is already built or visually closed. It proves that the foundation on which that retained work will be authored is ready, bounded, compatible with the accepted H1 public lifecycle and reviewable.

## Sequencing boundary with ART-01

H2F-GATE consumes ART-01 only through its published `PREFOUNDATION_INPUT`: renderer-independent/source-facing demand, source triage, assembly/dimensional grammar, representative real assets and known gaps. **ART-01 PASS is not a predecessor of this Gate.**

The Gate is the causal point that freezes the production foundation. After Gate PASS, ART-01 resumes its effective Unity benchmark, render-specific tuning, fresh-author/agent smoke test and frozen candidate on this accepted baseline. H2F may not claim ART-01 `KEEPER_READY`; ART-01 may not freeze its final benchmark on a private/pre-Gate foundation.

## PASS-before-work acceptance contract

- **Positive claim:** the project has closed the material pre-H2 capability decisions, adopted the selected stack under the dependency/IP policy, proved the components together on one non-keeper fixture, proved the selected foundation state survives or reconstructs through the accepted H1 lifecycle according to an explicit boundary, and documented a reproducible restoration path and replacement boundaries.
- **Mandatory positive evidence:** (1) closed capability register covering every H2F mandatory category; (2) final `ADOPT_NOW / AVAILABLE_ASSET / DEFER / REDUNDANT / REJECT / NO_ADOPT` disposition matrix; (3) exact package/source/adoption ledger for every material adopted dependency; (4) frozen Unity package/project baseline and URP configuration; (5) complete selected-foundation-state → H1 lifecycle classification/host matrix; (6) H2F-03 integrated fixture evidence including third-person traversal, worldbuilding coexistence, real Quaternius humanoid animation/retarget proof and fresh-author/agent operation; (7) composed H1 materialize → observe → reconcile → rematerialize → accepted clean-rebuild evidence with the full selected stack present; (8) clean restore/import reproduction using the documented lawful/manual inputs; (9) bounded profiler sanity evidence evaluated only by the predeclared H2F-03 diagnostic/pathology oracle; (10) explicit residual/backlog list for deferred categories and future replacement triggers.
- **Negative gates:** FAIL if a capability required by CITY-07/H2 still has unresolved `SPIKE_REQUIRED`; if a material dependency floats or lacks exact adoption/license truth; if material selected foundation state has no declared H1 lifecycle host/expectation; if the stack is only proven package-by-package or only before H1 lifecycle operations; if material selected state is lost, falsely classified as unsupported drift or requires undocumented hand repair after materialize/reconcile/rematerialize/clean rebuild; if representative Quaternius content still relies on hidden unsupported render/material fallback; if clean restoration depends on undocumented local caches/assets; if a plugin-private data model becomes canonical Juego2 semantics; if CITY/H2 would still have to choose between competing foundation tools while authoring keeper content; if an enumerated H2F-03 performance pathology reproduces; or if the H2F fixture is presented as keeper acceptance.
- **Non-claims:** no ART-01 PASS/keeper-ready claim, no final keeper geometry, no ART-02 visual closure, no Living World simulation, no town-wide/shipping performance budget, no final narrative/audio stack and no claim that deferred categories can never be revisited.
- **Allowed residuals:** later artistic tuning, content breadth, ordinary non-pathological profiler findings/optimization work, H3+ narrative/behaviour/audio choices and deliberately deferred capabilities whose absence does not constrain CITY-07/H2. Residuals may not include unresolved tool choice for any capability actually required by the representative keeper slice.
- **Evaluation method:** documentary dependency/provenance review + exact project/package inspection + H1 lifecycle-boundary inspection + effective Unity integrated-fixture visual/play evidence + composed H1 public-lifecycle reproduction + clean-restoration reproduction + diagnostic profiler/pathology review + fresh-author transcript.
- **Consumed predecessors:** accepted H0/H1 authority and Unity bridge, ART-01 `PREFOUNDATION_INPUT` source/demand/assembly truth, H2F-00 ecosystem coverage, H2F-01 decision evidence, H2F-02 exact adoption/lifecycle classification and H2F-03 integrated compatibility/lifecycle proof.

## Required frozen outputs

### 1. Foundation manifest

Publish one human- and machine-readable-enough manifest or equivalent reviewed set identifying:

- Unity editor version;
- active render pipeline and exact package versions;
- selected official Unity packages;
- selected third-party tools and their exact versions/commits where applicable;
- admitted free/source-content libraries and provenance class;
- required local/account-gated source inputs;
- selected presets/adapters and their stable Juego2-side identities;
- generated/transient data that must not be treated as source authority.

The manifest may reference existing package locks/adoption records rather than duplicate them, but a fresh Worker must be able to discover the complete frozen baseline without reconstructing it from chat history.

### 2. Closed capability register

Every mandatory H2F category must end in one of the final dispositions. `SPIKE_REQUIRED` is forbidden at Gate for any CITY-07/H2-relevant capability.

For deliberately deferred areas such as final dialogue/narrative, audio middleware, streaming, advanced NPC behaviour or multiplayer, the register must say why deferral does not constrain the current keeper milestone.

### 3. Exact adoption and legal/provenance closure

Every material `ADOPT_NOW` dependency/source must satisfy `Docs/engineering/DEPENDENCY_IP_POLICY.md` at the exact adopted version/source state.

Asset Store or account-gated acquisitions must record lawful acquisition/provisioning without committing restricted bytes merely for convenience.

Free web/source content must retain source and license provenance sufficient for future derivatives and notices.

### 4. H1 lifecycle compatibility boundary and proof

Freeze the H2F-02 selected-foundation-state lifecycle matrix as part of the Gate evidence. Every material state family required by the selected stack must declare:

- lifecycle class/host;
- source of truth;
- materialize expectation;
- observation/drift treatment;
- reconcile ownership/expectation;
- rematerialize/clean-rebuild preservation or deterministic reconstruction path.

The Gate must review the H2F-03 effective composed lifecycle with the full selected stack present:

```text
clean/restored project
-> materialize
-> observe
-> one bounded legal reconcile operation through the accepted H1 public boundary
-> rematerialize
-> accepted H1 clean rebuild
-> reopen/run the fixture
-> compare every material state family with its declared lifecycle expectation
```

This requirement does **not** reopen H1 or require H1 to understand arbitrary plugin-private graphs. It proves the chosen boundary: H1-managed state remains under accepted H1 contracts; retained realization state is preserved in an admitted host without becoming canonical Arkus truth; generated/transient state is disposable and reproducible; manual inputs are restored only through the declared lawful path.

Any material state loss, false unsupported-drift report, hidden hand-repair step or non-reconstructible generated dependency blocks the Gate until routed to its causal owner.

### 5. Clean restoration proof

From a clean checkout/environment consistent with the accepted H1 restoration model:

```text
restore repository/package-manager inputs
-> provision documented lawful/manual source inputs
-> open/import with pinned Unity baseline
-> reproduce required project settings/presets/adapters
-> compile/import without hidden package drift
-> open/run the H2F integration fixture
-> confirm representative render/material, player/navigation and character-animation paths
```

The proof does not require an impossible redistribution of licensed assets. It requires the missing manual steps to be explicit and sufficient.

### 6. Integrated fixture retention

Retain the H2F integration fixture and evidence as a **non-keeper regression fixture** until at least H2-GATE. Later Workers may use it to detect foundation drift, but they may not substitute it for CITY-07/H2 keeper evidence.

### 7. Performance sanity interpretation

H2F-GATE consumes the **predeclared diagnostic oracle from H2F-03**. The profiler evidence is required, but ordinary frame-time/FPS/draw-call/triangle/memory values are not standalone PASS/FAIL thresholds in H2F.

The performance portion blocks the Gate only when an H2F-03 enumerated foundation pathology is reproduced and causally attributed to the selected baseline: crash/OOM/hard hang, reproducible uncaught selected-stack error on the normal path, runaway/repeating condition preventing repeated traversal, selected capability unavailable in its frozen target configuration, or deterministic foundation-induced stall/resource exhaustion preventing the prescribed bounded traversal on two clean attempts.

All other profiler observations are recorded as diagnostic residuals/optimization inputs for later scale/performance work. The Worker/Reviewer may not invent a new numeric performance threshold after seeing the capture.

### 8. Change-control rule after PASS

After Gate PASS, a new material tool/dependency may enter the keeper path only when one of these is true:

- it fits an already admitted content/source class and follows its existing ART/dependency policy;
- measured evidence exposes a blocker and an explicit H2F amendment adopts/replaces the relevant tool;
- a later causal phase owns a capability intentionally deferred by H2F.

Convenience, novelty or a promising Asset Store listing alone is not enough to silently alter the frozen baseline during ART-01/CITY-07/H2.

## PASS only if all are true

- `WP-H2F-00`, `01`, `02` and `03` have independently satisfied their written claims;
- every mandatory capability category has a final disposition and every CITY-07/H2-required capability has a usable selected solution or intentional `NO_ADOPT` design;
- no required `SPIKE_REQUIRED` remains;
- all material adopted dependencies/sources have exact adoption, license/provenance, role and replacement records;
- every material selected foundation-state family has an explicit H1 lifecycle class/host and observe/reconcile/rebuild expectation;
- URP and the selected project-wide render/material baseline are active and representative Quaternius content renders truthfully;
- the integrated non-keeper fixture proves the selected worldbuilding, player/camera/input/navigation and character-animation baseline together;
- the composed H1 lifecycle completes with the full selected stack present and every material state family is preserved or reconstructed exactly according to the H2F-02 matrix, without false unsupported drift or undocumented hand repair;
- a fresh author/agent can use the documented Juego2-side adapter/preset/public surfaces without inventing hidden plugin authority;
- clean restoration/import is reproducible with documented lawful/manual inputs;
- profiler evidence exists under the declared comparison context and no enumerated H2F-03 foundation pathology reproduces; ordinary non-pathological profiler results remain diagnostic residuals rather than post-hoc blockers;
- the retained foundation manifest/register makes the stack discoverable to future Workers;
- the fixture remains explicitly non-keeper and no CITY/ART/H2 product claim is smuggled into this Gate.

## Negative gates

FAIL if any of the following is true:

- unresolved required tool choice remains for CITY-07/H2;
- exact package/dependency identity or license/provenance is unknown;
- package versions drift implicitly or rely on local cache state;
- material selected foundation state lacks an H1 lifecycle classification/host;
- selected tools only work in isolated demos and not in the composed Juego2 fixture;
- the composed fixture works before H1 operations but required foundation state is lost, corrupted, falsely reported as unsupported drift or manually repaired after materialize/reconcile/rematerialize/clean rebuild;
- unsupported/fallback materials are hidden by screenshots or replacement proxies;
- clean restore cannot reproduce the baseline from repository state plus documented lawful/manual inputs;
- an enumerated H2F-03 performance pathology reproduces and remains unresolved;
- a new numeric profiler threshold is invented during execution/review and used as an H2F PASS/FAIL rule;
- one plugin becomes the only definition of canonical road/building/NPC/world semantics;
- a direct Unity/plugin mutation path is presented as canonical Arkus authoring;
- unselected spike packages remain accidentally embedded in the project baseline;
- or the Gate passes because “everything installed” despite unresolved lifecycle, integration or authoring-boundary failures.

## Definition of Done

H2F freezes one deliberately selected, H1-lifecycle-compatible and reproducible production baseline. ART-01 can then execute its effective visual candidate/PASS on that foundation, after which `WP-CITY-07` and H2 receive both the frozen toolchain and keeper-capable visual vocabulary. Subsequent keeper work can focus on **making the game**, while any later foundation change has an explicit causal trigger and adoption path instead of arriving as opportunistic dependency drift.
