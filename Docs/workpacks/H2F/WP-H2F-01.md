## Claim

Every H2F candidate whose choice is expensive to reverse and cannot be decided honestly from documentation has received the minimum real-project spike needed to select one baseline before keeper production.

## Sequencing rule with ART-01

H2F-01 consumes ART-01 only as a **pre-foundation input source**: current demand/coverage truth, source triage, assembly/dimensional grammar, representative real assets and known visual/source gaps. It must not require ART-01 to have completed its effective Unity visual benchmark, agent-composition smoke test, frozen candidate or PASS.

The causal order is:

```text
ART-01 PREFOUNDATION_INPUT
-> H2F-00
-> H2F-01
-> H2F-02
-> H2F-03
-> H2F-GATE
-> ART-01 effective CANDIDATE / PASS
```

H2F spikes may reveal that a proposed source/material/tool choice is inadequate. That finding is foundation-selection evidence, not a substitute ART-01 readiness verdict. Final keeper-ready visual composition remains downstream of H2F-GATE.

## PASS-before-work acceptance contract

- **Positive claim:** the bounded H2F-00 uncertainty queue has been resolved into an explicit final disposition matrix and one coherent recommended baseline.
- **Mandatory positive evidence:** (1) H2F-00 register consumed; (2) real Unity/source evidence for every retained spike; (3) comparison notes against the actual Juego2/Quaternius target rather than generic package demos; (4) final `ADOPT_NOW / AVAILABLE_ASSET / DEFER / REDUNDANT / REJECT / NO_ADOPT` matrix; (5) owner-visible visual judgement for spikes whose discriminator is appearance/feel; (6) unresolved/manual acquisition blockers separated from technical failures.
- **Negative gates:** FAIL if serious candidates are selected only from documentation; if every candidate is installed “just in case”; if visual/runtime fit is judged on a vendor demo instead of representative assets; if the spike mutates keeper CITY geometry; or if a plugin is selected because it is feature-rich while duplicating a simpler admitted solution without measured benefit.
- **Non-claims:** this WP selects but does not yet make the selected stack the project baseline. H2F-02 owns exact adoption/migration. It also does not claim ART-01 keeper readiness.
- **Allowed residuals:** deferred capabilities not required by CITY-07/H2; final fine-tuning of adopted settings; optimization packages whose need depends on later profiling.
- **Evaluation method:** smallest named Unity/source-content spike per decision + human visual/play review where relevant + bounded technical checks.
- **Consumed predecessors:** H2F-00 discovery, ART-01 `PREFOUNDATION_INPUT` source/demand/assembly truth, H1 accepted Unity bridge and dependency/IP policy.

## Mandatory spike families when H2F-00 retains competing candidates

The Worker does not need to spike weak/rejected alternatives. For the following families, however, a real spike is required whenever more than one plausible approach survives H2F-00 or the selected approach has material compatibility uncertainty:

1. **Render/URP migration** — actual Quaternius/Juego2 materials, custom shaders, transparency and representative source-project content under the proposed URP baseline.
2. **Linear worldbuilding** — road/path/slope/kerb/edge realization using the leading spline/road approach, including how an AI-authored typed intent can map to it without plugin-private state becoming canonical.
3. **Terrain/vegetation** — terrain/elevation plus vegetation placement/exclusion around roads/buildings/thresholds; inspect authoring cost and obvious runtime cost.
4. **Water/shoreline** — only if water is part of the H2/CITY retained view or near-term island identity; compare the simplest adequate native/custom approach against any retained external winner.
5. **Window/interior depth** — compare actual architectural need against Quaternius Source solutions and any retained fake-interior candidate; reject redundancy.
6. **Character animation** — actual Quaternius humanoid with the serious animation-library candidates. At minimum compare the same-emitter Quaternius animation source against external gap fillers where both are retained. Inspect Humanoid avatar mapping, feet, hands, root motion, stylized motion fit and retarget artifacts.
7. **Animation Rigging/IK** — one bounded interaction or contact correction if this capability is proposed for H2.
8. **Navigation** — selected navigation solution on representative slope/threshold/obstacle geometry, without implying H3 schedule semantics.
9. **Fog/weather** — only if an external solution survives the survey; compare against the admitted URP/native baseline at the target PS2+ visual language.
10. **Performance helpers** — only when H2F-00 presents evidence that the representative slice needs a non-native LOD/instancing/batching solution. Do not adopt speculative optimization middleware by default.

## Stack-selection rules

Prefer the smallest coherent stack that satisfies the target and remains automatable/reproducible.

Selection must explicitly consider:

- already-owned Quaternius Source functionality;
- visual-language fit;
- Unity 6.3/URP compatibility evidence;
- authoring cost for humans and Astra;
- reproducibility and source/provisioning burden;
- exact license/EULA implications;
- runtime/editor footprint;
- authority/replacement boundary;
- duplication with other selected tools;
- whether the capability is truly needed before CITY-07/H2.

“Free” is not sufficient reason to adopt a dependency. “Paid” is not sufficient reason to reject one if it demonstrably removes substantial bespoke work and remains replaceable/admissible.

## Required output

- final candidate disposition matrix;
- exact baseline intent passed to H2F-02;
- retained visual captures/short play evidence for material visual decisions;
- spike project/change ledger, with non-adopted experiment residue removed or isolated;
- manual acquisition/provisioning list;
- explicit deferred/rejected register with reasons;
- dependency-policy questions that H2F-02 must close at exact adopted versions.

## PASS only if all are true

- every H2F-00 `SPIKE_REQUIRED` item affecting CITY-07/H2 has a resolved decision;
- selected render/worldbuilding/character choices have been exercised on representative real assets where documentation was insufficient;
- the final baseline contains no unexplained overlapping tools for the same role;
- Quaternius Source capabilities were not ignored before selecting duplicate external tooling;
- actual Quaternius character animation/retarget fit is proven rather than assumed from generic humanoid compatibility;
- visual decisions that materially affect Juego2 receive owner/art-direction inspection;
- selected tools remain downstream implementation helpers, not canonical semantic authorities;
- no keeper CITY-07 content is claimed or frozen by the spike fixtures.

## Negative gates

The acceptance-contract negative gates are binding. “Install both and decide later in H2” is an explicit FAIL for a capability whose choice is part of this foundation freeze.
