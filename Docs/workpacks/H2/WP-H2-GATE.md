# WP-H2-GATE — Keeper visual + AI world-authoring benchmark

Status: **DORMANT / NOT_STARTED**  
Class: PRODUCT GATE / `PRODUCT_CHECKPOINT`  
Depends on: `WP-H2-01` PASS + `WP-H2-03` PASS + `WP-ART-02` PASS + accepted CITY-07 keeper  
Blocks: H3 persistent-actor/runtime implementation

## Gate claim

A fresh capable AI author can use accepted Arkus public surfaces to understand, maintain and locally improve a visually representative keeper Juego2 zone in Unity; the player can traverse it in third person while representative characters occupy it; and the result already expresses the approved visual language without disguised proxy/greybox gaps.

## PASS only if all are true

- the representative Puente -> Casco -> Bar chain is keeper and playable;
- ART-02 has approved the representative final visual language;
- required environment roles/connections are `KEEPER_READY`;
- at least six approved character presentations occupy the slice with H2-03 minimum behaviour;
- human third-person inspection confirms scale, route rhythm, thresholds, character/environment proportions and representative occupancy are credible;
- a fresh author completes inspect -> discover -> local semantic improvement -> validate/apply -> materialize -> inspect/play -> reconcile/rematerialize through accepted public surfaces;
- the edit does not silently regenerate or damage unrelated accepted content;
- at least one composition is reused/varied with observable lower authoring effort than first legal assembly while preserving constraints;
- missing required coverage or unsupported edits fail visibly rather than being replaced with final-looking improvisation;
- parity/truthfulness remains intact after the authoring loop;
- evidence includes playable/third-person observation, not only screenshots or top-down/editor views.

## Negative gates

FAIL if the scene reads as greybox plus pasted assets; if `PROXY_VISUAL`/`COVERAGE_BLOCKED` satisfies final readiness; if NPC proxies are claimed as H3 routines; if the fresh author must read implementation source or use hidden Unity-only authority; or if visual approval is inferred solely from deterministic tests.

## Superseded CITY-08 claim

This gate owns the final integrated proof formerly assigned to `WP-CITY-08`: public discoverability, bounded correction, constraint-preserving reuse and measurable first-assembly vs reuse benefit. Do not run a second duplicate CITY authoring gate after H2-GATE.

## Definition of Done

After PASS, the main uncertainty handed to H3 is behavioural depth: persistent people, time, schedules and daily-life systems. H3 should not need to rediscover the representative game's fundamental visual identity or rebuild the H2 keeper world as a different art direction.
