# WP-PA-14 — Living World integration review

Status: **FROZEN PLAN / DORMANT UNTIL PREREQUISITES**  
Class: **RESEARCH INTEGRATION / NON-FOUNDATIONAL**  
Execution: **DEFERRED_INTEGRATION**  
Depends on: `WP-PA-13` PASS + merge + DocSync **and** an accepted H2 playable-shell phase boundary/closure sufficient to plan H3+ consumers  
Blocks: no current H1/CITY workpack; informs future H3/H4/H7 planning

## Objective

Integrate only accepted Juego2 PA findings into a coherent product model and concrete future-phase inputs after the project knows what the H2 playable shell actually established.

This WP exists to prevent two opposite errors:

1. implementing H3/H4 by rediscovering all Living World product semantics during coding;
2. freezing H3/H4 runtime contracts now against an H2 architecture that has not been planned/proven yet.

## Required inputs

- accepted PA-01..13 Juego2 results only;
- current cross-cutting amendments;
- current CITY product seed and accepted H2 boundary at execution time;
- donor `PA-12_PLAN_INTEGRATION_REVIEW.md` only as a checklist source — old M9/M10 routing is obsolete.

## Work

- produce the final accepted/rejected/later capability matrix;
- reconcile ownership among routine, agency, relationships, beliefs, rumours, memory, work, activities, player action, events, investigation, governance and control/budgets;
- define a small composed scenario suite that proves causal composition without requiring every system at maximum depth;
- map research requirements into **candidate** H3/H4/H7 workpack/ADR questions using the then-current architecture;
- identify H2 interaction/action seams that later Living World consumers need without retroactively redesigning H2 unless a real blocker exists;
- preserve H5 cinematics/GameFlow and H6 combat as separate owners that must consume/return structured Living World consequences rather than being swallowed by PA;
- list empirical proofs that remain implementation-owned.

## Required composed scenarios

At minimum the synthesis must cover:

1. ordinary readable day with interruption/recovery;
2. NPC-originated actor→actor consequence chain;
3. knowledge asymmetry + selective information flow;
4. past event changing a later decision through bounded memory;
5. work/activity state creating a visible opportunity or conflict;
6. player-originated action whose consequences continue while absent;
7. missed event reconstructed through legitimate traces;
8. governance decision producing third-person consequences;
9. clumsy play recovering versus deliberate sustained destabilisation transforming the town;
10. FULL/ABSTRACT transition preserving meaningful causal state as a later implementation requirement.

No new numeric population target is frozen here merely because the donor PA-12 mentioned one; current product-seed and implementation evidence own scale.

## Acceptance

- only accepted PA findings are integrated;
- every important state/decision has one clear semantic owner;
- no circular ownership requires one subsystem to know another's private internals;
- future workpack deltas target real current phase boundaries, not old M9/M10 or imagined H2 APIs;
- research findings are clearly separated from implementation proof;
- the composed product still prioritizes playability, legibility and normal life over simulation complexity for its own sake.

## Negative gates

FAIL if PA-14 invents a missing mechanism instead of reopening its causal PA, resurrects donor runtime architecture by convenience, or claims a playable/runtime proof from paper scenarios.

## Definition of Done

Future H3/H4/H7 planning receives one reviewed Living World research package grounded in Juego2, with explicit scenarios, ownership, failure modes and deferred empirical questions. If no further PA research gap remains, the PA research programme is complete; later runtime validation belongs to its implementing phases.
