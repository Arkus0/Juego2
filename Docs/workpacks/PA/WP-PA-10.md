# WP-PA-10 — Autonomous Events & Causal Chains research

Status: **FROZEN PLAN / NOT_STARTED**  
Class: **RESEARCH / NON-FOUNDATIONAL**  
Execution: **REMOTE_RESEARCH**  
Depends on: `WP-PA-09` PASS + merge + DocSync  
Blocks: `WP-PA-11` only

## Objective

Define how interesting multi-step events can emerge from accepted actor/player causes while remaining bounded, understandable and capable of termination rather than becoming procedural soap opera.

## Required inputs

- accepted PA-01..09 findings;
- donor `PA-08_PLAN_AUTONOMOUS_EVENTS.md` as preregistration input, remapped to canonical Juego2 PA-10;
- intentional-transformation and playable-causal-city amendments.

## Research questions

- event initiation from goals, conflicts, material state and player actions;
- micro/meso/macro event classes only where useful;
- participant recruitment and opportunity windows;
- escalation, de-escalation, resolution and explicit termination;
- bounded branching and cooldown/salience interaction;
- authored constraints without a hidden director puppeting NPC decisions;
- how ordinary normality recovers after weak causes while strong sustained causes can produce real transformation;
- how chains remain reconstructible by PA-11 without becoming omniscient quest logs.

## Deliverables

- canonical PA-10 dossier;
- at least one 3+ step NPC-originated chain;
- at least one player-originated chain sharing the same lifecycle vocabulary;
- termination/de-escalation mechanisms;
- storyteller-puppetry and infinite-escalation negative controls;
- H4/H7 future-consumer notes.

## Acceptance

A 3+ step causal chain can originate from a legitimate actor cause, recruit/affect others for explicit reasons, remain bounded and terminate without a privileged script deciding every step.

Negative gate: random event generation that merely assigns roles to actors after deciding the story in advance cannot be presented as autonomous agency.

## Deferred proof

Pacing feel, event frequency, CPU budgets, authoring volume and final runtime orchestration require later implementation evidence.

## Definition of Done

PA-10 defines an event ecology compatible with both normality and intentional transformation. Reviewer PASS names `WP-PA-11` next.
